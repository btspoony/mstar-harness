# Architecture Governance

Governance, not a rewrite: the codebase is converged batch by batch, and every batch leaves the product working with one path per semantic. A batch that adds an abstraction, directory or interface without migrating its callers, or that leaves the replaced implementation alive beside the new one, is not progress and is rejected at Acceptance.

**Procedure SSOT** → `mstar-coding-behavior` → `references/architecture-governance.md` (target state, the seven properties and their owners, closed-batch conditions, batch selection by total complexity, rejected moves, stop conditions).

## Boot

- PM: `mstar-harness-core` + this entry's routing; `mstar-phase-gates` + `mstar-dispatch-gates` before the first implement dispatch; `mstar-conventions` (path symbols) and `mstar-host` (invoke capability).
- Discovery rubric: `mstar-audit` → `references/codebase-audit.md` § scope variants (`simplify`) — read it as the method for ranking candidates, not as a dispatched seat.
- Execution and QC seats: `mstar-coding-behavior` → `references/architecture-governance.md`; `mstar-sdd` when the batch is multi-task; `mstar-coding-behavior` → `references/constraint-ladder.md` when a settled rule needs enforcing; `mstar-doc-corpus` → `references/adr.md` when a structural decision is promoted.

## Execute

1. **Discover.** Resolve the round's budget once before any batch: `rounds N` (a positive integer) when the invocation states it, one batch when it does not; a value that is not a positive integer is refused with the offending value and both retries (omit the token, or pass a positive integer such as `rounds 1`). This budget bounds consecutive batches inside one invocation only; under an iteration each batch is one of that iteration's business plans, so the iteration's own plan budget can end the work earlier. Then perform the recon of `mstar-coding-behavior` → `references/architecture-governance.md` § Recon in this session, over the whole codebase or over the `path|subsystem` scope when that token is given; a recon that cannot be completed stops here, names the missing evidence and the read that would close it, and selects no batch. Then rank candidate moves from that recon by the `simplify` rubric (`mstar-audit` → `references/codebase-audit.md`), keeping only evidence the reads produced and only candidates inside the `path|subsystem` scope when that token is given. `dry-run` returns the six inventories with the ranked candidates and the already-observed baseline in the response, then exits, writing nothing — no plan write, audit run directory, report or evidence file, scout dispatch, issue capture, ADR write, edit, or claimed net-complexity figure. Otherwise run the same pass as a read-only audit, keep its evidence, and record the six inventories in the round's governance plan — the plan that carries this round's batch rows — or in the audit report this round reuses.
2. **Select one batch.** Take the candidate with the lowest total complexity per `mstar-coding-behavior` → `references/architecture-governance.md` § Choosing the batch, and drop every candidate its § Not a finding list rejects. One batch per plan row.
3. **Prepare.** The batch is a normal plan: `specify → clarify → plan` per `mstar-phase-gates`, and its plan records the recon's six inventories so the move is traceable to what the round read. The behaviour baseline lands before the move (`mstar-audit/references/codebase-audit.md` § Write the report states the behavior-preservation gates) and its AC carries the closed-batch conditions as acceptance evidence — every live caller accounted for, the replaced path absent, the baseline observed, the rule landed on a constraint or recorded as an authorized residual. A caller the batch cannot migrate rejects the whole move; the old path is never kept alive beside the new one.
4. **Execute, lock, then review.** PM dispatches a development seat (SDD for multi-task); the batch lands the settled rule on the strongest available constraint (`constraint-ladder.md`) or records an authorized residual, then independent QC and PM Acceptance judge that complete move (`mstar-roles/references/project-manager/acceptance.md`).
5. **Next batch.** Record the batch's net complexity, then check the round's budget — the only stop that needs no fresh candidate list; spent, the round ends. If it remains, re-run discovery over the current tree and only then apply the candidate stops (no eligible move, or the next move needs a decision), so an accepted batch can make a move eligible that the previous ranking could not see. Under an iteration, that iteration's plan budget may end the work earlier; that is the iteration's stop, not this round's. Invoking this command opts into the batches its budget allows without a confirmation prompt between them; it is never approval for a merge (that authorization belongs to the delivery path), a destructive migration, or a product or architecture decision. A destructive migration or a required product or architecture decision captures an issue and ends the round per that reference's § Stop conditions.

## Close-out

Report each batch as: the move; the parallel path, scatter or layer it removed; the caller churn; the behaviour baseline that proved preservation; the constraint now holding the rule or the residual it left; and the stop condition that ended the round. When the round selects no batch, its governance plan still records the recon and that outcome; create it through the normal plan gates if this round has none. When the round ends on its budget or a needed decision, the previous ranking is stale: capture as issues only leftovers whose evidence still applies to the final tree — an earlier read the last batch did not invalidate, or a confirmation made after it (`mstar-project-governance` § Issue capture) — and list the rest as leads that need a fresh ranking in the next run; never rescan solely to close the round. Accepted structural decisions live in `{ADR_DIR}`, and the plan rows remain the delivery record.
