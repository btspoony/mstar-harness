# Adding a named role to the Morning Star role system (review/audit seats)

## Context

Morning Star's SDD loop defines a per-task reviewer (L2) and the `audit` task category defines a read-only audit executor — but until v2.1.0 neither had a named role. Host generics (`generalPurpose`, omp `reviewer`/`task`) carried identity, NEVER rules, and load contracts scattered across `mstar-sdd` templates and host mappings, with no SSOT reference file. v2.1.0 introduced **`code-reviewer`**: one role, dual duty — default SDD per-task reviewer (L2), `Task category: audit` = full `mstar-audit` carrier. This doc captures the reusable method and the traps the QC waves caught.

## Guidance

### 1. Role core (three artifacts)

| Artifact | Content |
|----------|---------|
| `agents/<role>.md` | Shell: `mode: subagent` + least-privilege permission profile (below) + role-binding stub (`mstar-roles` reference + mandatory first steps) |
| `skills/mstar-roles/references/<role>.md` | Identity, modes, load contract (Required Skill Dependencies), NEVER section |
| `skills/mstar-roles/SKILL.md` | Role Reference Mapping row + Role → typical topic skills matrix row |

### 2. Permission profile (least privilege)

- `edit`: deny all; allow only the role's own write scope — `{SDD_DIR}` review reports (`<harness-root>/sdd/*.md`, `sdd/**/*.md`) and audit plan outputs (`<harness-root>/plans/*.md`, `plans/**/*.md`) — **for every harness-root variant in use** (`.mstar/`, `.agents/`, `.mstar/` + `.worktrees/**/` equivalents).
- `bash`: deny all; allow read-only git (`diff/log/show/blame/shortlog/stash list/branch <read-only forms>/status/rev-parse`) + lightweight analysis (`wc/rg/cloc/scc/tokei`) + audit read-only checks (`tsc --noEmit`, `npm audit`, `pnpm audit`).
- `task`: deny all; allow only `explore` + `scout` (read-only built-ins; audit-mode fan-out additionally gated by Assignment `Delegation: allowed (scout/explore only, read-only)`).

### 3. Wiring checklist (every surface, or the role is only half-wired)

1. `skills/mstar-sdd/SKILL.md` per-task loop + `references/task-reviewer-prompt.md` — name the role as L2 reviewer (not `qc-specialist*`), keep fresh-per-task / no-sticky / no-full-suite semantics
2. `skills/mstar-dispatch-gates/SKILL.md` — informal per-task review role line
3. **All** host references: `omp.md` + `cursor.md` + `kimi.md` + `zcode.md` + `opencode.md` — one host only is a cross-host gap
4. `skills/mstar-harness-core/SKILL.md` Task category routing (if the role owns a category, e.g. `audit`)
5. `commands/*.md` routing body (entry frontmatter may stay with PM — entry shim vs executor is a deliberate split)
6. `packages/engine/src/roles.ts` `ROLE_MAPPING` + `packages/engine/test/roles.test.ts` (count-agnostic assertions; real-corpus integration test validates entry → on-disk reference)
7. `README.md` + `README_CN.md` role tables (bilingual, same round)
8. `.changes/unreleased/<slug>.md` fragment — include **every** package that ships the change (`packages: root, opencode, engine` when engine data changes)

### 4. Gotchas (learned via QC tri, two fix waves)

- **Prefix-wildcard bash allows admit mutating variants.** `"npm audit*"` matches `npm audit fix`; `"npm audit --json*"` matches `npm audit --json fix`. Use **exact forms** (`"npm audit"`, `"npm audit --json"` — no trailing `*`) and add **explicit deny rows before the allows** (`"npm audit fix*": deny`). Same for `tsc --noEmit` (deny `tsc --noEmit false*` / `--noEmit=*`) and `git branch` (deny `-d/-D/-m/-M/-c/-C`; allow only `--show-current*`, `--list*`, exact `-a`, exact `-r`).
- **Permission globs must cover the actual harness root.** Discovery documents `.mstar → .agents`; this repo's own root is `.mstar/`. An allowlist with only `.mstar`/`.agents` silently blocks the role's own report/plan writes in `.mstar`-rooted repos. Cover all variants in use.
- **Generated bundles go stale silently.** `packages/opencode/harness-agents/` is gitignored and regenerated by `bun run opencode:bundle-assets`. Editing `agents/<role>.md` in a later fix wave without re-bundling leaves the publish artifact stale — QA's `diff agents/<role>.md harness-agents/<role>.md` gate caught it. Re-run bundle after **every** source edit; treat bundle==source diff as a DoD gate.
- **Engine `ROLE_MAPPING` order should mirror the SKILL.md mapping table** — auditors diff SSOT vs engine data row by row.
- **Host live agent lists refresh only on plugin reload.** A new role id is absent from the live `task.agent` schema until reload; document the generic fallback (omp `reviewer`/`task`, Cursor `generalPurpose` + C5b binding) in the wiring text.
- **Real-corpus engine tests can go red pre-merge** when the control checkout is on the base branch (new `references/<role>.md` not yet merged): deterministic, not a regression — document the `MSTAR_CONTROL_SKILLS` override in the test source.
- **L2 ≠ L3.** The task-reviewer role never occupies a QC seat: `assertTriIdentity` (qc-specialist/-2/-3), QC single/targeted re-review, and `review-responsibility-boundaries` L3/L4 semantics stay untouched; the L2 row names the new role as default.

### 5. Audit-mode delegation discipline

- Fan-out of read-only `scout`/`explore` subagents belongs to the audit **executor** under Assignment `Delegation: allowed (scout/explore only, read-only)`; PM orchestrates only. Tool availability (task allow) ≠ delegation grant — the reference must say so, and leaf anti-recursion red lines still apply (no delegation → `Blocked`).

## Retired role: `qa-engineer` (PR #681)

`qa-engineer` was removed from this system: the QA role was replaced by **PM Acceptance**, and the engine's `ROLE_MAPPING` / `agents/` / `skills/mstar-roles/references/` no longer carry it (`.changes/unreleased/remove-qa-role.md`). The method above still holds for live roles — the retired 13→14 example below (QA-era counts) is history, not a template: a new role is one `agents/<role>.md` + one `references/<role>.md` + one `ROLE_MAPPING` row, verified against the current corpus rather than against a remembered count. Historical `mandatory` `qa_gate` rows recover through ordinary prepare with `--qa-gate pm-acceptance`; the L2 reviewer (`code-reviewer`) and independent QC seats are unaffected.

## Why This Matters

A named role makes dispatch identity, boundaries, and load contracts a single-file SSOT instead of prose scattered across host fallbacks — and the shell permission profile makes the read-only contract structural, not just prompt-level. The wiring list is the drift surface: missing one host reference or one generated artifact silently degrades the role on that surface.

## When to Apply

- Adding any new role to `mstar-roles` (the mapping lives in engine `ROLE_MAPPING`: 13 entries today, one per agent shell under `agents/`, with `fullstack-dev*` and `qc-specialist*` sharing one reference file each; the count is deliberately not asserted).
- Reviewing an existing role shell (check exact-form allowlists, harness-root variants, bundle sync).
- Wiring a role across hosts or routing a task category to a named executor.

## Examples

`code-reviewer` (iteration v2.1.0, plan `20260811-code-reviewer-role`): dual-mode role — SDD L2 per-task reviewer + `mstar-audit` carrier; 8-surface wiring; engine `ROLE_MAPPING` 13→14; two QC fix waves caught the `--json*` wildcard hole, the `.mstar` edit-glob gap, and the stale bundle (all fixed; final tri Approve 0/0/0, QA Pass).
