# Host write gates: classify the authority route before any document judgment

## Context

The governance store (`{HARNESS_DIR}/store.db` + WAL/SHM) and the retired project registers must be protected from direct writes at every host entry. The cutover plan's G4b/G4a slices wired a DB-aware **authority route** into four hosts; the plan QC tri still found a Critical hole (dsh) plus case-sensitivity and honesty gaps — the gate pattern, not the individual hosts, is the reusable lesson.

## Guidance

- **Classify before document judgment, in both enforcement modes.** The authority check (`isStoreAuthorityTarget` → `readAuthorityRoute`) must run before the document-classifier's `kind === null` early return — that early return is exactly how `store.db`/`-wal`/`-shm` hand writes passed silently on dsh. Veto `store.direct-write-refused` (including WAL sidecars), `project.register.retired`, and `store.authority-unavailable` unconditionally — warn mode still vetoes authority-class refusals.
- **Preserve the documented escape hatches exactly.** Pre-activation fall-through (`store.not-initialized` / `store.not-active` → the legacy register path, contract §7) stays; the G4a boundary holds — only authority-class refusals veto, readable-authority findings keep the repair escape.
- **Fold case, then walk ancestors, then canonicalize.** Authority basenames match case-folded (on Darwin/APFS, `Store.db` / `RESIDUALS.json` bypass exact-case predicates); register roots resolve through the precedence chain `direct → aliased → caseFolded(caller path) → caseFolded(landing path)`; symlink-landed targets classify by on-disk identity after `realpath`. Unconditional folding is fail-closed (over-gates case variants on case-sensitive volumes) — accepted.
- **A host without a refusal channel is warn-only — say so.** OpenCode's `tool.execute.before` is typed `Promise<void>`: it cannot abort. There the gate logs the decision and the write still executes; documentation must state that plainly instead of claiming a refusal the runtime cannot perform. Enforcing hosts (dsh/omp/ZCode hook) carry the veto; the audit surface must still classify case-variant targets so the log line is not silently skipped either.
- **Keep the mirrored copies semantically identical.** The *path glue* is now single-sourced in the engine (`packages/engine/src/host-gate-paths.ts`: `isStoreAuthorityTarget` / `caseFoldedRegisterRoot` / `landedPathOf` / `caseFoldedDocKind`, issue #442) and every host imports it — the copies had drifted into a real two-link-alias bypass, so a re-derivation per host is the defect, not the design. What stays per-host is the refusal decision and its envelope (which codes a host can actually stop), with per-site case-variant fixtures. The committed ZCode hook artifact is regenerated by its build script, never hand-edited.
- **Review lesson:** a grep anchor can miss the post-route code path. The "register-name fold is dsh-only" finding was adjudicated by reading the post-route document path (the folded walk feeds the shared engine classifier) rather than by accepting the grep — test-locked parity fixtures beat a negative grep.

## Extension: the same rule on the READ side

Cutting over to a **DB execution authority** re-ran this pattern across six consumer surfaces (engine read adapter, CLI, four OMP tools, OMP pre-hook, two OMP extensions, three DSh gates, OpenCode, shared hook) and produced the same class of defect five more times. Additions worth carrying forward:

- **The authority decision must precede every file read, not just every write.** A surface that computes its verdict and only then asks "is the file route still authoritative?" has already read retired bytes. Instances fixed: the DSh dispatch seams, DSh `beforeDispatch`/`beforeMerge`, the OMP pre-hook, the OMP `phase2` bind, the model-handoff binding-mode classifier. The review invariant: *on a path that will refuse, no file is opened.*
- **Classify the LANDED target, not only the caller's textual path.** A target whose textual path is not a canonical harness document can `realpath` onto a retired `status.json` / `workflows/<id>/snapshot.json` and skip the check entirely (an OMP pre-hook Warning, found after three hosts already classified landed targets). `harnessDocKindOfTarget` returning `null` for a non-canonical basename is the trap: classify `landed = realpath(resolved)` too and derive the execution target from caller **then** landed, excluding `register`.
- **A synchronous surface reuses the engine's synchronous guard; it does not reimplement one.** The DSh gate path could not await, so the engine exported its existing `assertExecutionFileReadAllowed` and every sync seam called it — one guard, no second definition, no signature change. The same guard also closed a **file-route default**: a synchronous catalog/digest builder that fell through to the retired register whenever the caller supplied no route facts was answering from leftover bytes on every synchronous call, including the shipped context provider. Where a sync surface genuinely cannot await the authority source, degrade to the honest subset (a version watermark) rather than serving the file answer.
- **A refusal must never degrade into a fallback.** The counterpart failure is a probe that treats "store exists but cannot be read" (busy/corrupt/schema-drift) as "no store, so read files". Discriminate explicitly: *no store file* ⇒ legacy/file route stays lawful; *unreadable store* ⇒ fail closed with the engine's own code. Both halves were Critical findings.
- **Enumerate the seams yourself; do not trust a coverage claim.** The fix that guarded two synchronous seams still left two more in the same file. Re-enumerating every synchronous read in the touched surface and stating, per entry, why it is guarded or needs no guard is what turned a partial fix into a closed one.

## Why This Matters

Direct-write protection lives at the host seam because the engine cannot see a raw `fs.writeFile` from a host process. A single missed entry (or a single bypassed predicate) turns the whole single-authority model into advisory text. The failure modes are all shape-level: early returns, exact-case matches, hosts that cannot abort, and copies that drift.

## When to Apply

Any host gate change in `packages/dsh/src/gates/`, `packages/omp/src/hooks/`, `packages/opencode/src/mstar.ts`, `hooks/src/mstar-write-gate.ts`; any new host adapter; the future one-home consolidation of the authority route into the engine.

## Examples

- FW-1 (`7dd740e3`): dsh `store-authority.ts` classification wired into `gateStatusIntent` (before the `kind === null` return) and the status-write adapter, both enforcement modes.
- FW-3 + wave 2 (`2e9d728b`, `45384cf6`): case-folded matching + `caseFoldedRegisterRoot` precedence identical across dsh/omp/ZCode/OpenCode, with per-site fixtures.
- FW-4 (`4f79ee02`): OpenCode documented warn-only with the API-typed reason; log line no longer claims refusal.
