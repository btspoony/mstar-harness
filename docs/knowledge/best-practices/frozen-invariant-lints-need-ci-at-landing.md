# Frozen-invariant lints must land CI-wired, and calibrate before narrowing

Source: plan 20261008-overdesign-lint-judge (#341); incidents I-000451, I-000434, I-000435.

## Lessons

1. **A lint that lands without a CI job decays.** `lint:hash-gates` shipped alongside PR #376 and was never wired into CI; when it was finally re-run on main it reported 49 frozen-rule violations (40 test byte-assertions, 4 canonical-assertions, 2 hash-assertions, 3 genuine gates). Per-site introduction history is unverified, but an unwired lint could not have caught any of them. Enforcement wiring is part of the lint deliverable, not a follow-up.
2. **New matchers over-report before they are calibrated.** The refusal-quality lint's first real-tree run reported 1,488 findings; a 13-site sampling table identifying the actual supply mechanism (typed constructor fields, envelope-scoped recovery fields, help-route-derived usage recovery) reduced the count to the genuine 70, then 80 after ownership separation. Calibrate hypothesis-gated — sample sites, identify mechanisms, then narrow — never blanket-allowlist or file-exempt.
3. **Fixture fidelity beats fabricated coverage.** A fixture that does not reproduce its historical class (arbitrary ordered arrays standing in for a filesystem-enumeration bug) manufactures false confidence. The honest disposition is an explicit `NOT MECHANICALLY COVERED` row pointing at the judged-example review layer.
4. **Exemptions on frozen invariants carry the rule's own evidence bar.** Per-site allowlist entries need justification + a real tracking issue; untriaged cohorts stay visible (CI `continue-on-error` with a named flip condition) instead of being excused silently.
5. **Cross-lint coupling: gate every cohort against all enforcing lints.** Fixing one lint's findings rewrites the same operator-facing strings another lint scans — refusal recoveries tripped help-reachability class 4, and static-message conversions tripped refusal-quality unreachable-recovery. Each remediation batch must run every sibling lint (no see-saw) before its allowlist entries are deleted.
6. **Linter semantics need honest escape hatches, bound one-marker-one-site.** Two operator-truthful cases cannot satisfy command/equality rules: production integrity gates that must compare hashes (completion-evidence, safe-purge) and operations with no honest CLI verb (legacy layout migration). Encode validated-reason markers (`// hash-gate: authorized — <reason>`, `// reachability: manual — <reason>`) with full-source lexical binding and strict one-marker-one-site consumption — per-line substring matching over-authorizes adjacent sites (found twice by review).
7. **Triage first at remediation scale.** Classifying every finding (remediation class + proposed fix + helper-shared grouping) before mass edits turned ~480 sites into mechanical batches; the residual failures were all blanket-rewrite misdirections (kind/phase-inaccurate guidance, template fallbacks) caught by per-task review.

## Current wiring (verified 2026-11-09)

The enforcement wiring this doc demands is now in place and must stay that way: `.github/workflows/ci.yml` runs `bun run lint:hash-gates`, `bun run lint:refusal-quality` and `bun run lint:help-reachability` as blocking steps (no `continue-on-error` anywhere in the file), each alongside its own unit suite in the scripts test step. The bounded exemption lists live in `scripts/lint-refusal-quality.allowlist.json` / `scripts/lint-help-reachability.allowlist.json`, each entry carrying `justification` + `trackingIssue` (e.g. `I-000872`, `Rule #341`) — the rule-4 evidence bar in practice.
