## A. Implementer `Task budget` (capacity semantics)

**A1 — Field labels and parser.** Assignment header field `**Task budget (implement / ops rounds)**: <value>`; the bare `Task budget` label is also accepted. Add `taskBudget?: string` to `AssignmentFields`, a two-label constant alongside `BUDGET_LABELS`, and one branch in the existing `parseAssignmentFields` loop (`packages/engine/src/dispatch.ts:62-81,132-150,168-188`). Reuse its case-sensitive label matching, trimmed values, optional list prefix and last-recognized-occurrence-wins behavior. The parenthesized label uses the bold-label grammar; the bare label works bold or plain. Do not widen the plain-label grammar or add another parser. Only `assignmentHeaderRegion` counts: body examples after its first Task heading, horizontal rule or single-`#` heading cannot satisfy or disable this gate (`dispatch.ts:213-234`). Existing review-seat `Budget` / `Return shape` labels and parsing stay unchanged.

**A2 — Value shape.** The value declares *one implementer round closing the task's declared Files list and verification gates*, citing the task's `Effort (agent-oriented)` band from `skills/mstar-conventions/references/effort-estimation.md:20-26` (XS/S/M/L/XL — no new scale). Effort remains an estimate; a multi-session band does not authorize a multi-round task or relax the one-round ceiling: split until each dispatched task can close its own Files and gates. Wall-clock is only an escape valve that triggers the overrun report, never a work target or a new numeric-minutes table. The validator checks presence only, not prose adequacy, sizing or elapsed time; PM's Prepare check owns those judgments. The Assignment is the validated carrier, with the value before the body marker. `mstar sdd task-brief` needs no generated shape change; PM copies the task's budget into the dispatch header.

**A3 — Enforcement and round discrimination.** Reuse the exact normalized `role`, `reviewSeat`, `category`, and `auditRound` calculations already in `validateAssignmentFields` (`dispatch.ts:442-445`); the new branch is the complement `!reviewSeat && !auditRound`. Role normalization strips one leading `@`, lowercases and takes the first whitespace token; audit detection uses `/^audit(?![A-Za-z0-9])/` after the existing prefix stripping. Thus `audit (secondary)` and `audit_secondary` stay audit rounds; `auditing` does not. “Implement / ops rounds” is the contract's name for this complement, not a newly inferred lifecycle phase: non-audit docs/Prepare specialists and orientation roles also receive the field requirement. `writable: false` still controls branch-form validation only; it is not a capacity exemption. Missing core fields retain their existing errors. No `Round kind`, execution-phase field, role whitelist or source-file inference is added.

Use `describeAbsence(fields.taskBudget)` unchanged for absent, empty/whitespace-only and case-insensitive exact `N/A`. Emit one violation **`assignment.field.task-budget-missing`**, severity **`high`**, with the absence reason and a fix naming A1/A2. This matches sibling `assignment.field.budget-missing` / `assignment.field.return-shape-missing` (`dispatch.ts:449-473`), not the unrelated required-field naming pattern. The gate returns `ok: false` (`:540`) — the frozen **fail**, dispatch-incomplete outcome; `error` is not the sibling severity value. Do not introduce a warning fallback, numeric validation or changes to review/audit result semantics.

**A4 — Overrun response (execution layer).** If the declared round cannot close its Files and verification gates, stop adding work and return `NEEDS_CONTEXT` or `BLOCKED` (existing SDD completion vocabulary, no new state). Persist completed steps, remaining implementation and checks, evidence paths, worktree/branch state and the concrete boundary reached. PM updates the task split under A5 and re-dispatches with a fresh budget; a continuation is not an automatic budget extension. An incomplete round never reports `DONE` / `DONE_WITH_CONCERNS` as a substitute for the remaining work.

**A5 — Criteria and split strategies (plan layer).** The runtime home is `skills/mstar-artifacts/references/plan-quality-bar.md`: add checklist item 7, *Task shape / session fit*, requiring each task's Effort band, one-round Files-plus-gates closure and a named split point. Preserve the existing scale (`skills/mstar-conventions/references/effort-estimation.md:20-26`). Reuse the actual four strategies from `skills/mstar-audit/references/pr-review.md:104`: **stack**, **by file group**, **horizontal (shared code first)**, **vertical (full-stack slices)**, applied to task boundaries with explicit interfaces and independent proof. Do not misquote that source as a different four-strategy list or inherit its PR line-count thresholds. `mstar-phase-gates` adds the fourth PM self-review question and matching quick-check item, both pointing to item 7; the main-plan template exposes the Effort/split-point slots without restating the policy.

**A6 — Mandatory anti-shortcut clause.** **Budget pressure MUST NOT shorten or waive any assigned scoped verification.** Verification authorization remains in `mstar-harness-core` § 定向执行与验证边界 (`skills/mstar-harness-core/SKILL.md:136-145`); item 7 is the runtime home of this capacity-specific prohibition. The implementer and continuation prompts MUST repeat this sentence beside their budget/overrun instruction so it cannot be read as optional, and MUST require A4 escalation for remaining checks. Assignment-template guidance and phase/dispatch/SDD summaries point to item 7 rather than defining alternative exceptions. This is the `pr-review.md:57-59` never-cut principle applied to implementation, not permission to reduce verification or expand it to a full suite.

## C. Phase-transition `todo` refresh discipline

**C1 — Duty.** At **every phase transition** (Prepare → Execute → InReview waves → Phase 3 close → Phase 4 PR → Phase 5 merge-ready → Phase 6 post-merge; likewise per-plan gate crossings), PM refreshes the host session `todo` list before the next action/dispatch. Append the next phase's entries and close the finished phase's completed entries; preserve any still-pending gate or future-phase item. Scoped primary sessions project only their assigned plan through handoff, never global Phase 3–6 tasks (`skills/mstar-iteration/references/command-shared-invariants.md:47-55`, `skills/mstar-iteration/references/phase-2-worktree-lease.md:57-59`).

**C2 — Projection, not SSOT.** `todo` entries reflect the existing snapshot phase/plan states and named plan/gate evidence; they cannot authorize or invent a state transition. Snapshot/plan artifacts remain authoritative, with no second state store. This is freshness discipline, not a new host hook/tool or deterministic enforcement mechanism; model/host behavior needs separate evidence.

## D. Engine residual guards (ride-alongs)

**D1 — R1 `migrate-target-ownership-guard`.** Keep the root lock in `applyMigratePlan` (`packages/engine/src/migrate.ts:919-934`), the source-version CAS/no-op (`:958-970`), additive order and final root-v2 commit (`:1057-1070`). Guard all three unprotected targets in `applyMigratePlanLocked`: archive `join(plan.root, plan.archive.file)` (`:974-975`), every notes file through `workflowTargetOf(notes.file)` (`:1003-1008`), and the optional roadmap seed through **`projectTargetOf(plan.roadmap.file)` at `:1051-1054`**. Absent → exclusive create; existing byte-identical → leave untouched; divergent → `CoordinationError("coordination.version-conflict", …)` under the root lock, leaving the conflicting file and root v1 unchanged. A late conflict can leave earlier additive outputs behind; retries converge on identical outputs. This is not an all-target transaction or a promise of zero writes before every target conflict.

Compare raw bytes: archive against the CAS-checked v1 source bytes; notes against UTF-8 `notes.lines.join("\n") + "\n"` when nonempty and zero bytes when empty; roadmap against UTF-8 `plan.roadmap.content`. Reuse the existing additive-only refusal pattern, **not** `stableJson` for these targets: snapshot/register guards compare JSON payloads (`:985-1000,1029-1046`), whereas archive preservation, JSONL and Markdown require byte identity. Preserve custom workflow/project resolution (`:949-950`), null-roadmap no-op and source-CAS refusal-before-writes. An exclusive-create collision must re-read and compare, never overwrite. No planner or existing JSON guard redesign.

**D2 — R2 `git-unavailable-timeout-regression`.** Correct contract: `gitRead` (`packages/engine/src/coordination.ts:2495-2505`) returns `undefined` only for a numeric nonzero exit status; spawn failure or timeout without a numeric status throws **`coordination.git-unavailable`** via `gitUnavailable` (`:2460-2483`). These are unavailable evidence, not proof of divergence, no-op or merge success. Tests exercise an existing public coordination operation that reaches this private helper; do not export it for testing or mock `execFileSync`.

Use isolated child Bun processes launched via absolute `process.execPath`, each with an explicit environment and `PATH` containing only its fixture directory. One fixture has no `git` (real spawn failure), one executable exits nonzero, one executable runs past the existing **10,000 ms** timeout (`:2450`). On POSIX use an absolute shebang/interpreter and an `exec`-replaced hanging process, with no PATH-dependent `env`, sleep utility or surviving grandchild. Record shim invocation so a missing/non-executable shim cannot masquerade as the timeout case. Do not change the parent test runner's PATH. Parent subprocess and Bun test timeouts must exceed the production timeout with cleanup margin; timeout errors and spawn errors assert the same public code but distinct causes. Nonzero-exit behavior and existing real-Git merge/no-op/revert discrimination remain separate controls. If Bun does not consult the shim PATH, reports timeout as a numeric exit, or cannot reap the child reliably, **STOP** with the observed mechanism and a scoped runtime-fix proposal to PM; do not lower production timeouts, silently skip the case or substitute mocked coverage. No runtime proof is claimed during Prepare.
