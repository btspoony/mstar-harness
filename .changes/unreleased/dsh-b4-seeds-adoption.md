- **dsh plugin**: pinned `dsh-llm-fallbacks` to `^0.1.7` (seed methods available at install) and **zero-config mstar role seeds** — on fallbacks mount, the plugin declares the 13 `mode: subagent` mstar role seeds into the fallbacks seed registry (persona = the `harness-agents/` mirror `description` + one mandatory-load guide line; `{{...}}` interpolation-hazard personas skipped + warned, never declared). The declaration merge-preserves the currently-seeded non-mstar ids from the readback (e.g. the upstream bundled preset roles) — upstream `declare` replaces the whole registry, so preservation keeps preset ids seeded; it re-fires idempotently per fallbacks (re-)apply (HMR/fiber swap), never from a one-shot latch. The 7 preset ids and the mirror-derived 13 mstar ids are disjoint by construction — both boot orders converge to the same 20-id fully-seeded registry.
- **dsh plugin**: the fallbacks adoption advisory is now **seeds-aware** — with the service present, the decision point first awaits the idempotent re-declare (closing the boot race) then reads the EFFECTIVE state and reports per mstar id: missing row (warn), seeded at default (silent, one debug), persona-overridden (warn + the revert entry: the `fallbacks/revert-seed` gateway / the settings-card rollback button); empty-persona warns fire only for non-seeded or overridden-empty rows; declare skips/conflicts (upstream code `persona-source`) merge into one warn. The structural `roles.list` read is preserved on the loader-fallback path (no service). Logger `mstar/fallbacks-advisory`.
