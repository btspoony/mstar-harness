category: Changed
packages: cli
---

- **The MCP server publishes one tool per command family instead of one per command.** `tools/list` was the largest fixed cost of every agent session: 113 tools and 173,340 characters of description + input schema (189,881 for the payload-composed input view), 66% of that description text being a `CLI: mstar … --flags` usage line a tool caller cannot run. Each family now publishes one `mstar_<family>` tool with a required `action` selecting a real command, a merged field set derived from the command descriptors, and a compact description (purpose, one line of required fields per action — including the exactly-one selector a union action such as `schema` requires — the `<family>.<action>` id shape `mstar_schema` accepts, and a payload pointer where the action has one). A shared field name whose per-action declarations disagree on type or enumerated values is not published for the whole tool; the description names it "varies by action" and `mstar_schema` carries each action's shape, so `tools/list` never advertises a request a later action refuses. Measured on the same probe: 113 tools → 33, description + input schema 173,340 → 32,670 characters. Output schemas are no longer published (154,471 → 0), so the old publication was 327,811 characters including them (~91k tokens) against 32,670 today (~9.1k tokens).
- **Admission is unchanged; the published family schema is enforced as an index of what each action takes.** Every call still resolves to its command's own descriptor and composed schema, so validation strictness, aggregated refusals, `defaultSessionId`/`defaultHarness` handling and the identity lock behave exactly as before; an unknown or missing `action` refuses with the family's real action list, every supplied top-level key no family member accepts, and the recovery — a key is not reported as invalid while some member still accepts it. Because a family publishes the UNION of its members' fields while admission validates the selected member's strip-mode schema, a top-level key that action does not accept now refuses before admission with a usage envelope naming the fields it does take and the recovery — a sibling action's field or a typo was previously dropped without a diagnostic, and a dropped FILTER reads as an applied one (an unfiltered page returned to a caller that asked for a filter). A session selector's refusal joins the same envelope (naming the actions that accept it) instead of short-circuiting it, a `payload` object's internals stay the selected action's own payload schema, and a family derives its tool name from the definition's authored `cli.path[0]` — the segment `mstar_schema --family` accepts, asserted equal to the id prefix across every definition — so the published name and the `mstar_schema` recovery cannot point at different families. The family field index and the rendered CLI/payload contract read a union input through one shared `anyOf` + `oneOf` traversal, and the `plan` family purpose states the bind asymmetry: the MCP action writes the engine row only, while a dsh-coordinating session that needs dsh-local ledger attribution uses the native `mstar_plan_bind`. `mstar_schema` remains the field-detail authority, and `renderCommandContract` no longer spends MCP description budget on CLI usage syntax.

- **MCP 服务器改为每个命令家族发布一个工具。** `tools/list` 是每个 agent 会话最大的固定成本：113 个工具、173,340 字符的描述与输入 schema（按 payload 组合视图计为 189,881 字符），其中 66% 的描述文本是工具调用方无法执行的 `CLI: mstar … --flags` 用法行。现在每个家族只发布一个 `mstar_<family>` 工具，必填 `action` 选择真实命令，字段集由命令描述符合并推导，描述保持紧凑（家族用途、每个 action 一行的必填字段——含 `schema` 这类联合 action 必需的「exactly one of」选择器、`mstar_schema` 接受的 `<family>.<action>` id 形状，以及带 payload 的 action 的指针）。同一字段名在各 action 上的声明若在类型或枚举值上不一致，则不再为整个工具发布该声明；描述会点名「varies by action」，各 action 的形状由 `mstar_schema` 承载，因此 `tools/list` 绝不会发布一个后续 action 会拒绝的请求。同一探针实测：113 → 33 个工具，描述与输入 schema 173,340 → 32,670 字符。输出 schema 不再发布（154,471 → 0），因此含输出 schema 的旧发布负载为 327,811 字符（约 91k token），今天是 32,670 字符（约 9.1k token）。
- **准入语义不变，但已发布的家族 schema 现在会按「每个 action 真正接受哪些字段」强制校验。** 每次调用仍解析到该命令自身的描述符与组合 schema，校验严格度、聚合拒绝、`defaultSessionId`/`defaultHarness` 处理与身份锁与之前完全一致；未知或缺失 `action` 会带家族真实 action 列表、所有成员都不接受的顶层字段，以及恢复路径一并拒绝——只要还有成员接受该字段，就不会把它判为非法。由于家族发布的是成员字段的**并集**、而准入只校验所选成员的 strip 模式 schema，所选 action 不接受的自顶层字段现在会在准入前拒绝，并以 usage envelope 点名它真正接受的字段与恢复路径——此前兄弟 action 的字段或拼写错误会被静默丢弃，而**被丢弃的过滤条件**读起来就像已生效的过滤（要求过滤的调用方拿到未过滤的一页）。session 选择器的拒绝并入同一个 envelope（并点名接受它的 action），不再提前短路；`payload` 对象内部仍归所选 action 自己的 payload schema；家族工具名改为由定义的 `cli.path[0]`（即 `mstar_schema --family` 接受的段）推导，并在全部定义上断言其等于 id 前缀，因此发布名与 `mstar_schema` 恢复路径不会指向不同家族。家族字段索引与渲染出的 CLI/payload 契约共享同一套 `anyOf` + `oneOf` 联合遍历；`plan` 家族用途写明 bind 的不对称：MCP action 只写引擎行，需要 dsh 本地台账归因的 dsh coordinator 会话使用原生 `mstar_plan_bind`。`mstar_schema` 仍是字段细节权威，`renderCommandContract` 不再把 CLI 用法语法计入 MCP 描述预算。
