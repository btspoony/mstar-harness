- **Phase 1 no longer commits harness artifacts**: the §2.3 integration-worktree checklist step 7 (reached through `iteration-start` §6) now pushes only the newly created `spec_integration_branch` (`git push -u`; the branch tip stays at the recorded base, satisfying the `phase-1-lock` readiness check that the pushed remote tip equal the live integration HEAD — enforced by the omp model-handoff runtime). Two artifact classes are now stated separately: compass / plans / the iteration package and other process artifacts are default-gitignored and never committed or pushed, while tracked `{SPECS_DIR}` reviewed edits are equally **not committed in Phase 1** — when `{SPECS_DIR}` resolves to a tracked path (`mstar-conventions` git tracking policy) they join the integration branch later via the Phase 3 close commit's tracked-subtree recipe (`phase-3-iteration-close.md` §3.5). Renamed the `iteration-start` / `iteration-loop` pre-commit checklists to pre-integration checklists (loop's `phase-1-autonomous-start` todo now completes on compass lock + integration-branch push), reworded the §1.6 uncommitted-docs exception, and dropped the stale Phase-1 "commit" from the plan-mode bridges (`_shared/plan-mode-bridge-core.md` gate + anti-pattern row, `cursor.md` Phase-1 Plan-mode gate, `cursor-`/`omp-`/`kimi-`/`zcode-plan-mode-bridge.md`).
