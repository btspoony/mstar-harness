- **A scoped MCP connection now pins its own workspace harness root.** The scoped mount injected only `--identity-env MSTAR_HOST_SESSION_ID` and left the control root to the server's `resolveProcessHarnessDir(process.cwd())`, so a connection serving one workspace rooted itself on whatever directory the host process was launched from. In practice an `mstar_issue_add` in an `mstar-harness` session was refused with `store.not-initialized` for an unrelated `deepseek-harness/.agents` path. The refusal was the SAFE outcome only because that foreign root holds no store: a wrong root that DOES hold one would have accepted the write silently, across projects, with the caller believing it wrote its own workspace. The mount now passes `--harness <the agent's own {HARNESS_DIR}>`, resolved per agent through the plugin's `HarnessResolver` so two agents in different workspaces each get their own pin; `--harness` also anchors the invocation workspace at the root's parent, so cwd-derived paths follow the pin. An unresolved root adds no flag (the CLI keeps its own probe and its `mcp.control-root-unresolved` refusal) and a deployment row that already declares `--harness` keeps its own value.
- **Regression coverage.** `packages/dsh/tests/scoped-mcp-mount.spec.ts` covers the pinned args, per-agent resolution across two workspaces, the no-root case, the explicit-row-pin case, and the pure `scopedMountArgsFor` contract (identity normalization, empty/null roots, non-array passthrough).

- **scoped MCP 连接现在钉住它自己 workspace 的 harness root。** scoped 挂载此前只注入 `--identity-env MSTAR_HOST_SESSION_ID`，把 control root 留给服务器的 `resolveProcessHarnessDir(process.cwd())`，于是服务于某个 workspace 的连接会扎根在宿主进程恰好启动的目录上。实际表现是：在 `mstar-harness` 会话里执行 `mstar_issue_add`，被以 `store.not-initialized` 拒绝，路径指向一个无关的 `deepseek-harness/.agents`。这次被拒绝只是**侥幸**的安全结果——那个外部 root 没有 store；若它有 store，写入会被跨项目静默接受，而调用方以为写的是自己的 workspace。现在挂载会传 `--harness <该 agent 自己的 {HARNESS_DIR}>`，通过插件的 `HarnessResolver` 按 agent 解析，因此分属不同 workspace 的两个 agent 各自得到自己的 pin；`--harness` 同时把调用 workspace 锚定到该 root 的父目录，使 cwd 派生路径一起跟随。无法解析出 root 时不追加该 flag（CLI 保留自己的探测与 `mcp.control-root-unresolved` 拒绝），deployment 行若已声明 `--harness` 则保留自己的值。
- **回归覆盖。** `packages/dsh/tests/scoped-mcp-mount.spec.ts` 覆盖带 pin 的 args、跨两个 workspace 的按 agent 解析、无 root 情形、显式行 pin 情形，以及纯函数 `scopedMountArgsFor` 的契约（identity 归一化、空/null root、非数组透传）。
