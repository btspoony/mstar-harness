---
category: Changed
packages: commands, cli
---

- **Bounded command contract discovery.** `mstar schema` now resolves one bounded selector: an exact command id returns the full leaf contract (description, effects, CLI syntax, caller/derived requirement ownership, input and payload JSON schemas), `--family <name>` returns a compact id+description list, and the issue-payload query keeps its published shape. The exactly-one-selector choice is expressed in the published input schema itself (an `anyOf` of strict per-selector objects), so `{}` or colliding selectors are refused at the input boundary with the grouped valid-selector guidance; CLI leaf help and MCP tool descriptions render the same descriptor table.
- **Typed `worktree check --tracks` payload.** The L2 `--tracks` option is a published typed array (`array of {worktreePath, workingBranch}`): the input schema, the runtime boundary validation, the CLI JSON decoding, and the discovery descriptor all share one schema, so the published contract no longer advertises a JSON-string form. Refusals carry indexed `tracks[N].<field>` paths before the gate runs, and the family keeps no JSON parser of its own. Payload options keep generic list decoding for a lone `--worktree` path (decoded as a one-element list), but a JSON object passed to a payload option is refused by the declared schema instead of being wrapped into a one-element array. All L1/L2 domain checks are unchanged.
- **Payload option lone values no longer comma-split.** A lone `--worktree` path containing a comma stays ONE literal asserted path: the payload-field branch of the CLI list decoding wraps the value verbatim instead of running `value.split(",")`, so `worktree cleanup --apply --worktree "<path,x>"` can no longer silently assert the comma-split fragments — with a fragment naming an unintended eligible worktree, `--apply` could have removed that worktree while the specified path was never considered. Multiple entries for a payload option now come only from an explicit JSON array or repeated occurrences of a variadic payload option; plain list options (e.g. `review seats --reviewers`) keep the comma-list convenience.
- **`worktree cleanup --worktree` accumulates repeated paths.** The option is declared variadic (`--worktree <path...>`), matching its documented repeat-to-narrow-and-assert contract: repeated DISTINCT occurrences now accumulate instead of last-wins, each occurrence stays one literal path (never comma-split), and an occurrence that is itself an explicit JSON array still decodes to its members. The published CLI syntax renders `--worktree <path...>`.

- **有界命令契约发现。** `mstar schema` 现在解析一个有界选择器：精确命令 id 返回完整叶子契约（描述、副作用、CLI 语法、调用方/派生需求归属、输入与载荷 JSON schema），`--family <name>` 返回紧凑的 id+描述列表，issue 载荷查询保持既有输出形态。「恰好一个选择器」的约束直接表达在发布的输入 schema 中（每个选择器一个 strict 分支的 `anyOf`），`{}` 或冲突选择器会在输入边界以分组后的合法选择器引导被拒绝；CLI 叶子帮助与 MCP 工具描述渲染同一张描述符表。
- **`worktree check --tracks` 载荷类型化。** L2 的 `--tracks` 选项是已发布的类型化数组（`{worktreePath, workingBranch}` 数组）：输入 schema、运行时边界校验、CLI JSON 解码与发现描述符共享同一份 schema，发布契约不再宣称 JSON 字符串形态。拒绝消息在门禁执行前携带带索引的 `tracks[N].<字段>` 路径，家族代码不再自带 JSON 解析器。payload 选项对单个 `--worktree` 路径保留通用列表解码（解码为单元素列表），但传给 payload 选项的 JSON 对象会按声明 schema 被拒绝，而不是被包裹成单元素数组。全部 L1/L2 领域检查保持不变。
- **payload 选项孤值不再按逗号切分。** 含逗号的单个 `--worktree` 路径保持为一条字面断言：CLI 列表解码的 payload 字段分支逐字包裹该值，不再执行 `value.split(",")`，因此 `worktree cleanup --apply --worktree "<path,x>"` 不会再静默断言切分出的片段——当某个片段恰好命名另一个合格 worktree 时，`--apply` 可能移除那个 worktree 而指定路径从未被考虑。payload 选项的多入口现在只来自显式 JSON 数组或可变参数（variadic）payload 选项的重复出现；普通列表选项（如 `review seats --reviewers`）保留逗号列表便捷形式。
- **`worktree cleanup --worktree` 累积重复路径。** 该选项声明为 variadic（`--worktree <path...>`），与其「可重复以窄化候选并断言归属」的文档契约一致：重复出现的不同路径现在会累积而不是 last-wins，每次出现都保持为一条字面路径（绝不按逗号切分），本身为显式 JSON 数组的出现仍解码为其成员。发布的 CLI 语法渲染为 `--worktree <path...>`。
