---
category: Changed
packages: engine
---

- **Terminal adoption no longer requires a recorded stop reason.** `adoptTerminalWorkflow` refuses a stopped/failed header whose `state.stop_reason` is missing no more — nothing in the engine ever writes that field, so the guard stranded every normally stopped workflow's ACTIVE coordinator session row behind a hand-edited SQLite row. The terminal-status check, registry membership, revision CAS, self-settlement refusal, adoption-record read-back and per-header ACTIVE-session coverage are unchanged, and the retired recovery branch is gone from the CLI refusal vocabulary.
- **An unregistered header is adopted by registry membership, not by its own status.** Eligibility is now "this header is not ACTIVE registry membership", so a header that left the registry without ever reaching a terminal value — reachable only by importing an unregistered snapshot — is adopted instead of refused with "no supported exit exists". The adoption terminalizes it to `stopped` with an `ended_at` in the SAME transaction as its adoption record and its settled session rows, so no committed state pairs an adoption with a still-running header; an already-terminal header keeps its recorded status and `ended_at` untouched. The registered-row guard, revision CAS, attestation validation, non-self-settlement refusal, per-header ACTIVE-session coverage and whole-transaction rollback are unchanged, and the "capture an issue with `mstar issue add`" dead end left the CLI refusal vocabulary with the refusal.

- **终态采纳不再要求记录停止原因。** `adoptTerminalWorkflow` 不再拒绝缺少 `state.stop_reason` 的 `stopped`/`failed` header——引擎中没有任何代码写入该字段，该门禁使每个经正常路径停止的 workflow 的 ACTIVE coordinator 会话行被困住，只能靠手工改 SQLite 脱困。终态状态检查、注册表成员、修订号 CAS、自结算拒绝、采纳记录回读与逐 header 的 ACTIVE 会话覆盖均保持不变；CLI 拒绝词汇中已移除失效的恢复分支。
- **未注册 header 依据注册表成员资格采纳，而非其自身状态。** 资格判定现为“该 header 不属于 ACTIVE 注册表成员”，因此一个离开注册表却从未到达终态的 header（仅能经由导入未注册快照产生）不再被 “no supported exit exists” 拒绝，而是可被采纳。采纳会在**同一事务**内把它置为 `stopped` 并写入 `ended_at`，与采纳记录和已结算的会话行一并提交，故不存在“采纳记录与仍在运行的 header”并存的已提交状态；已经是终态的 header 保持其记录的 status 与 `ended_at` 不变。已注册行门禁、修订号 CAS、attestation 校验、非 self-settlement 拒绝、逐 header 的 ACTIVE 会话覆盖与整事务回滚均保持不变；“capture an issue with `mstar issue add`” 死路文案随该拒绝一并从 CLI 拒绝词汇中移除。
