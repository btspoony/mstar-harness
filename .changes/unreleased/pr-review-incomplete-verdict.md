- **A PR review can now report `incomplete` instead of failing or asserting a pass** (requested by issue #503). `PR_VERDICTS` gains the neutral fourth token and `computePrTally` takes an optional `incomplete: { reason, unscanned }`: when supplied, `verdict` becomes `incomplete` while `scorePct`, `band` and the four counts stay the count-derived ones, and the chat header becomes four lines — `incomplete · <score>% (<band>, partial)` + the unchanged tally line + `cause: <reason>` + `unscanned: <csv|none>`. It is neither a pass nor a failure and never authorizes merge; without the declaration every existing run stays byte-identical (verdict, score, band and two-line header).
- **Both published surfaces enforce the declaration.** The `mstar.review/v1` envelope requires `incomplete` exactly when `verdict` is `incomplete` and rejects it on every other verdict (`review.missing-incomplete` / `review.incomplete-malformed` / `review.incomplete-unexpected`, with `tally.verdict` still equal to the top-level verdict); the Markdown report requires the `incomplete_reason` + `unscanned` frontmatter pair for that verdict and rejects it elsewhere (`prreview.report.missing-incomplete_reason` / `invalid-incomplete-reason` / `missing-unscanned` / `invalid-unscanned` / `incomplete-unexpected`), skipping the tally-mismatch check for this token alone while the `score_pct` recompute still runs. `mstar pr-review tally` gains `--incomplete-reason <text> --unscanned <csv>` (supplied together) and reports every invalid tally field — those two flags and the three count flags — in one refusal; `mstar schema` publishes the new optional envelope field, and a malformed fact is now held to the producer's single-line rule (a CR/LF in the cause or in an unscanned entry is refused).
- Updated the `mstar-audit` pr-review reference — verdict lists, the single `incomplete` trigger list and the settled-vs-declared rule (§ Time budget and Stage 3 now point at it), the partial display, the envelope/report carriers, the override invariant and one explicitly-labelled override row — and the entry surfaces (`commands/amazing-pr-review.md`, `docs/commands.md`, `README.md`, `README_CN.md`) now name all four tokens and that rule. The locked deduction schedule, bands and the settled display contract are unchanged.

- **PR review 现在可以报告 `incomplete`，而不必失败或谎称通过**（issue #503 提出）。`PR_VERDICTS` 增加这个中性的第四个 token，`computePrTally` 接受可选的 `incomplete: { reason, unscanned }`：提供后 `verdict` 变为 `incomplete`，而 `scorePct`、`band` 与四个计数保持由计数推导的值，聊天头部变为四行 —— `incomplete · <score>% (<band>, partial)` + 不变的 tally 行 + `cause: <reason>` + `unscanned: <csv|none>`。它既不是通过也不是失败，且**永不**授权合并；未声明时，既有运行保持逐字节不变（verdict、分数、band 与两行头部）。
- **两个已发布表面都强制该声明。** `mstar.review/v1` envelope 仅在 `verdict` 为 `incomplete` 时要求 `incomplete`，并在其他 verdict 上拒绝它（`review.missing-incomplete` / `review.incomplete-malformed` / `review.incomplete-unexpected`，且 `tally.verdict` 仍须等于顶层 verdict）；Markdown 报告在该 verdict 下要求 `incomplete_reason` + `unscanned` frontmatter 组合、其他 verdict 下拒绝（`prreview.report.missing-incomplete_reason` / `invalid-incomplete-reason` / `missing-unscanned` / `invalid-unscanned` / `incomplete-unexpected`），并仅对该 token 跳过 tally 不一致检查，`score_pct` 重算仍照常执行。`mstar pr-review tally` 新增 `--incomplete-reason <text> --unscanned <csv>`（须成对提供），并一次性拒绝全部非法 tally 字段（这两个 flag 与三个 count flag）；`mstar schema` 发布新的可选 envelope 字段，且畸形 fact 现与生产端共用同一条单行规则（cause 或 unscanned 条目含 CR/LF 即被拒绝）。
- 更新 `mstar-audit` 的 pr-review 参考 —— verdict 列表、唯一的 `incomplete` 触发清单与 settled/declared 规则（时间预算与 Stage 3 改为指向它）、partial 展示、envelope/报告承载字段、override 不变式，以及一行明确标注的 override 示例 —— 同时各入口表面（`commands/amazing-pr-review.md`、`docs/commands.md`、`README.md`、`README_CN.md`）列出全部四个 token 与该规则。锁定的扣分表、band 与既有展示契约保持不变。
