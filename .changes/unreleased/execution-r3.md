- Added the **assembled-package Node regression** `packages/cli/test/execution-package.node.test.mjs` (run with `node --test`). It drives the BUILT CLI bundle `packages/cli/dist/mstar-harness.js` as a subprocess through the ACTIVE DB transport — `workflow register` (creation), the coordinator and plan-pm `plan bind`s, `plan prepare`, `plan show` (read), `plan bind --resume-ref` (read-only resume) and a `plan progress` write plus its exact retry — against a populated temporary store whose authority is built by the built engine's own producers over real `node:sqlite`. Every CLI claim is re-checked against the engine's public readers and against `node:sqlite` directly, and the chain additionally asserts the current-generation semantics: the active route writes no root `status.json` and no workflow snapshot, the store is the only persistence route, and an identical retry replays the recorded receipt instead of re-committing.
- The same file re-derives the **generated consumer manifests** from the bytes on disk: every declared source/generated file digest, every source/generated tree digest (the producer's canonical tree walk, including symlink handling), every copied instruction tree (`copy` = exact target equality, `merge` = byte-identical superset), each entrypoint's declaration by an actual package/plugin surface, each package's own declared runtime floor, and each per-consumer evidence document against the aggregate manifest. `hooks/mstar-write-gate.mjs` must be byte-identical to the ZCode consumer's recorded generated artifact.
- The committed **ZCode hook bundle** is exercised as the host runs it (stdin PreToolUse envelope + exit code) under Node: it refuses a retired root `status.json` and workflow-snapshot write on an ACTIVE authority (`execution.direct-write-refused`), refuses the authority database (`store.direct-write-refused`), and keeps the pre-activation document gate (silent pass, plus the hard-enforcement `status.invalid-json` block).
- The regression states explicitly what it is NOT: no native host process, no installed binary, no TypeScript source import. OMP/DSh/OpenCode entrypoints are Bun or other-runtime targets covered only by generated-manifest parity, while H2's populated `phase2-launches` fixture recipe (catalog plan registration, a `phase-2-execute` workflow with lease-scope metadata, a DB-prepared Assignment, and both session binds) is executed against the built engine generation to show a real OMP-shaped database fixture runs under Node.
- Regenerated the committed ZCode hook bundle `hooks/mstar-write-gate.mjs` from `hooks/src/mstar-write-gate.ts` (R17) and committed the generated `hooks/execution-consumer.json` with the five per-package evidence documents under `packages/*/execution-consumer/` and `execution-consumer/zcode.json`.
