- **The MCP connection publishes the caller-declared `sessionId`, with no launcher opt-in.** Every command whose CLI declares `--session-id` now publishes it as an optional per-call input, and the supplied value is admitted. It is a **bearer identity on this transport**: `executionContextFor` turns it into `context.caller`, the engine resolves the caller's OWN coordinator binding from it, and knowing a live session id is therefore enough to act as that session (`workflow.register` still passes `allowUnsetSessionId: true`, so a NULL-creator registration stays legal). Authorization is unchanged — that binding row plus the `--expect` CAS token — and no binding lookup, role check or CAS check is weakened. A local stdio server is launched by the host inside a single-user trust domain, so refusing the value protected nothing; exposing the server beyond the local host would need authentication at the transport, not an unpublished field.
- **`mstar mcp --trust-caller-session-id` and the `mcp.caller-identity-unavailable` refusal are deleted.** With the selector published there is no unpublished-field path left, so a supplied `sessionId` meets the ordinary input contract and one refusal code covers the whole surface. `plan prepare`/`progress`/`complete` and every other identity-requiring action now run on the MCP surface instead of redirecting to the CLI for lack of a host-proven identity.
- **The identity-missing refusal and the `mstar schema` MCP requirement name the value to pass**: the calling session's id — dsh exports it as `DSH_SESSION_ID` — as `sessionId` on MCP; `--session-id` or `MSTAR_HOST_SESSION_ID` on the CLI (`DSH_SESSION_ID` is also a CLI source on dsh). Both texts keep the rule: the identity only attributes the write; the binding and `--expect` token authorize it.
- **Launchers and docs follow.** omp's `mcp.json` drops the removed flag; its `mcp-identity` extension keeps its behavior — it still injects the host session id per call and still REPLACES a caller-supplied value. The dsh bundle row comment, both packages' READMEs, the two host references and the `dsh-native-identity-channels` ADR restate the same rule.

- **MCP 连接发布调用方声明的 `sessionId`，不再需要启动方开关。** 凡是 CLI 声明了 `--session-id` 的命令，都在 MCP 上把它作为可选的按调用输入发布，并接受调用方传入的值。它是**本传输上的 bearer 身份**：`executionContextFor` 把它变成 `context.caller`，引擎据此解析调用方**自己**的 coordinator 绑定，因此知道一个活跃会话的 id 就足以以它行事（`workflow.register` 仍传 `allowUnsetSessionId: true`，因此 NULL creator 的注册依然合法）。授权不变——仍是那条绑定行加上 `--expect` CAS 令牌——没有任何绑定查找、角色校验或 CAS 校验被放宽。stdio 服务器由宿主启动、处在单用户信任域内，拒绝该值并不保护任何东西；要把服务器暴露到本地主机之外，需要传输层认证，而不是「不发布字段」。
- **删除 `mstar mcp --trust-caller-session-id` 与 `mcp.caller-identity-unavailable` 拒绝。** 选择器既已发布，就不存在「未发布字段」这条路径：传入的 `sessionId` 走普通输入契约，整个面只保留一个拒绝码。`plan prepare`/`progress`/`complete` 以及其他需要会话身份的操作，现在直接在 MCP 面上执行，不再因为缺少宿主可证身份而被推回 CLI。
- **身份缺失拒绝与 `mstar schema` 的 MCP 要求改为指出该传什么**：MCP 上传 `sessionId`，值为调用方会话的 id（dsh 以 `DSH_SESSION_ID` 导出）；CLI 上传 `--session-id` 或设置 `MSTAR_HOST_SESSION_ID`（dsh 上 CLI 也读 `DSH_SESSION_ID`）。两处文本都保留这条规则：身份只标注写入归属，授权由绑定与 `--expect` 令牌完成。
- **启动配置与文档同步。** omp 的 `mcp.json` 去掉已删除的开关；其 `mcp-identity` 扩展行为不变——仍按调用注入宿主会话 id，且仍**替换**调用方自带的值。dsh bundle 行注释、两个包的 README、两份 host 参考与 `dsh-native-identity-channels` ADR 均改为陈述同一条规则。
