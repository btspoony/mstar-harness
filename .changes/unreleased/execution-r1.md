- Added the **consumer-v1 source/package inventory producer** `scripts/execution-consumer-manifest.ts`. `collectExecutionConsumerManifest(repoRoot)` records, per consumer (engine, CLI, DSh, OMP, OpenCode, ZCode), the canonical build-input closure (source trees plus config and build-script files), the generated output closure (build output trees plus the public entry artifacts), the entrypoint, the exact runtime target/floor and the declared capability, plus the canonical copied-instruction trees each package bundles from the repo-root `skills/`, `commands/`, `agents/` and `assets/` corpus. It reuses the existing build layouts (each package's `build`/`bundle-assets`/`build-client` script and `scripts/build-zcode-hooks.ts`) instead of a second build system.
- The recorded closures cover the real public surfaces: DSh's exported `./client` bundle, every engine declaration output inside `dist`, and OMP's package-root `hooks`/`extensions`/`tools` convention mirrors and plugin manifest. A changed transitive input — an engine module re-exported by the entry, a package-local module, or the engine source the ZCode hook inlines — invalidates the manifest even while the old generated bytes remain in place. A recorded digest is parity evidence, not a claim that the output was compiled from that source; only the real package build proves that.
- Added `verifyExecutionConsumerManifest(manifest)` as a generation-independent validator: it re-derives every fact from the bytes on disk — build inputs, generated outputs, copied instruction trees, package `engines` floors, capability, `packageRoot` and digests — and refuses with a stable `consumer.*` code on any drift. Every path is canonicalized (symlinks resolved) and containment-checked before any read or write, so a symlinked file, tree root, manifest leaf or staging path that would leave the checkout refuses instead of being followed; manifest writes land through a staging file opened exclusively with no-follow (`O_CREAT|O_EXCL|O_NOFOLLOW`) and are then renamed.
- Copied-instruction parity is self-contained: a link is recorded by its tree-relative canonical target and resolved bytes, so a copy matches only when its link structure is portable, and a link escaping its own tree refuses. `copy` targets must match the source tree exactly; `merge` targets (the OpenCode-only agent overlay) must contain every source file byte-identically. The OMP build input closure includes the `.omp-plugin/plugin.json` source that `bundle-assets` mirrors to the package root.
- Added the CLI `bun scripts/execution-consumer-manifest.ts --repo . --write|--check`: `--write` emits `packages/<id>/dist/execution-consumer.json` for engine/CLI/DSh/OMP/OpenCode plus `hooks/execution-consumer.json` (the ZCode plugin-root copy) and excludes that basename from the output digests, and `--check` re-verifies every written manifest without writing. `--write` additionally publishes one canonical evidence document per consumer at `<packageRoot>/execution-consumer/<consumer>.json` — exactly one `consumer-v1` entry per document, serialized canonically with one terminal LF through the engine's own value form — outside every recorded closure so publishing it cannot invalidate a tree digest, and `--check` verifies each one as well (a missing, non-canonical or multi-entry document, or one disagreeing with the aggregate manifest, refuses with exit code 1 instead of passing silently). Missing or empty build output refuses, malformed documents return the stable schema refusal instead of a raw error, and the producer never fabricates parity. The OpenCode `decision-only` capability is recorded explicitly rather than advertised as a writer.
- Packaging evidence only: no version surface, package metadata, generated bundle or installed state is modified, and the committed ZCode hook is not regenerated here.

- 新增 **consumer-v1 源/包清单生产者** `scripts/execution-consumer-manifest.ts`：`collectExecutionConsumerManifest(repoRoot)` 为每个消费方（engine、CLI、DSh、OMP、OpenCode、ZCode）记录规范构建输入闭包（源目录树加配置与构建脚本文件）、生成输出闭包（构建产物目录树加公开入口产物）、入口点、精确运行时目标/下限与声明能力，以及各包从仓库根 `skills/`、`commands/`、`agents/`、`assets/` 语料打包的规范复制指令树。它复用现有构建布局（各包 `build`/`bundle-assets`/`build-client` 与 `scripts/build-zcode-hooks.ts`），不引入第二套构建系统。
- 记录的闭包覆盖真实公开面：DSh 导出的 `./client` bundle、`dist` 内全部 engine 声明产物，以及 OMP 的包根 `hooks`/`extensions`/`tools` 约定镜像与插件清单。任一传递输入变化——入口再导出的 engine 模块、包内局部模块，或 ZCode hook 内联的 engine 源码——即使旧生成字节仍在，也会使清单失效。记录摘要是一致性证据，不是“产物由该源编译而来”的断言；只有真实包构建能证明后者。
- 新增与生成过程解耦的校验器 `verifyExecutionConsumerManifest(manifest)`：从磁盘字节重新推导每项事实——构建输入、生成产物、复制指令树、包 `engines` 下限、能力、`packageRoot` 与摘要——任何漂移都以稳定的 `consumer.*` 码拒绝。所有路径在任何读取或写入前先做规范化（解析符号链接）与容器检查，指向仓库外的符号链接文件、目录树根、清单叶子或暂存路径一律拒绝而非跟随；清单写入经以 `O_CREAT|O_EXCL|O_NOFOLLOW` 独占打开的暂存文件后 rename 落地。
- 复制指令一致性自带可搬移语义：符号链接按树内相对规范目标与解析后字节记录，因此只有链接结构可搬移时复制才匹配，链接逃逸自身目录树即拒绝。`copy` 模式要求目标树与源树完全一致；`merge` 模式（仅 OpenCode 的 agent overlay）要求每个源文件按字节一致地出现。OMP 的构建输入闭包包含 `bundle-assets` 镜像到包根的 `.omp-plugin/plugin.json` 源文件。
- 新增 CLI `bun scripts/execution-consumer-manifest.ts --repo . --write|--check`：`--write` 为 engine/CLI/DSh/OMP/OpenCode 写出 `packages/<id>/dist/execution-consumer.json` 并写出 `hooks/execution-consumer.json`（ZCode 插件根副本），同时将该文件名排除在输出摘要之外；`--check` 在不写入的前提下重新校验每份已写清单。`--write` 另为每个消费方发布一份 canonical 证据文档 `<packageRoot>/execution-consumer/<consumer>.json`——每份恰好一个 `consumer-v1` 条目，并经由引擎自身的规范值形式以单个结尾 LF 序列化——且位于所有已记录闭包之外，因此发布它不会使目录树摘要失效；`--check` 亦逐份校验（缺失、非 canonical 或多条目、与聚合清单不一致均以退出码 1 拒绝，绝不静默通过）。构建输出缺失或为空即拒绝，畸形文档返回稳定的 schema 拒绝而非原始异常，生产者不伪造一致性。OpenCode 的 `decision-only` 能力被显式记录，而不是宣称可写。
- 仅为打包证据：不修改任何版本面、包元数据、生成 bundle 或已安装状态，也不在此处重新生成已提交的 ZCode hook。
