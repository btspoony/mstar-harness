- Added the file-native **workflow notes ledger** to the engine (`execution-ledgers.ts`): `appendWorkflowNote` appends ONE canonical `{version:1,id,workflowId,sessionId,kind:"note",ts,text}` line to `<control root>/workflows/<id>/notes.jsonl` under the maintenance exclusion and the per-workflow status lock, with C1's synchronous current-session assertion running as the last step before the `fsync`ed byte write (no `await` between them). The migrated `{kind:"note",ts,text}` lines and the inline PlanRow `notes` stay byte-for-byte preserved — nothing rewrites, reorders or compacts a retained ledger, and no note becomes a DB event.
- A record's identity is the caller's stable id: the same id with the same body replays without appending, the same id with a changed body refuses `execution-ledgers.id-conflict`, and an accepted id recorded twice refuses `execution-ledgers.ledger-foreign` instead of picking a winner. A crash-cut partial line of the very record being written is reconciled into exactly one accepted line; an unterminated tail that is not that record's own partial refuses `execution-ledgers.tail-unreconciled` with every retained byte left in place.
- Provenance is the bound session's own scope: the record's `workflowId`/`sessionId` are checked against the session the engine already authorizes — never inferred from a model-supplied field, a cached selection or the note body — and a mismatch refuses `execution-ledgers.scope-mismatch`. The append creates only the ledger line: it never materializes a control root, a root register or a retained workflow dir, and refuses a symlinked/non-regular target or an absent workflow dir with `execution-ledgers.target-untrusted`, so an active-epoch write can never land through a link or recreate a retired root.
- Added the pure coverage projection `normalizeWorkflowNotesCoverage` (`notes-v1`) for the coverage producer: canonical path, file hash, the ordered historical lines with their `(source-file-sha256, line-index)` identity, the ordered accepted ids with per-line hashes, duplicated ids, counts and the unaccepted tail — inspectable facts instead of a hidden scan.

- 为引擎新增**文件原生工作流笔记账本**（`execution-ledgers.ts`）：`appendWorkflowNote` 在 maintenance 排他锁与按工作流的 status 锁内，向 `<control root>/workflows/<id>/notes.jsonl` 追加**一条**规范化的 `{version:1,id,workflowId,sessionId,kind:"note",ts,text}` 行，且 C1 的同步当前会话断言是 `fsync` 字节写入之前的最后一步（两者之间无 `await`）。迁移产生的 `{kind:"note",ts,text}` 历史行与 PlanRow 内联 `notes` 保持逐字节不变——不重写、不重排、不压缩保留账本，笔记也绝不变成 DB 事件。
- 记录身份是调用方提供的稳定 id：同 id 同正文按重放处理、不追加；同 id 正文变更拒绝 `execution-ledgers.id-conflict`；同一已接受 id 出现两次拒绝 `execution-ledgers.ledger-foreign`，绝不在两个候选中挑一个。正在写入的记录自身的崩溃截断半行会被收敛为恰好一条已接受行；不是该记录自身前半段的未终止尾部拒绝 `execution-ledgers.tail-unreconciled`，且所有保留字节原样不动。
- 出处即绑定会话自身的范围：记录的 `workflowId`/`sessionId` 与会话（引擎本就在授权的那一个）比对，绝不从模型字段、缓存选择或笔记正文推断；不一致拒绝 `execution-ledgers.scope-mismatch`。追加只创建账本行本身：绝不物化控制根、根注册表或保留工作流目录，对符号链接/非普通文件目标或缺失的工作流目录以 `execution-ledgers.target-untrusted` 拒绝，因此活动 epoch 的写入既不会穿过链接落地，也不会重建已退役的根。
- 为覆盖生产者新增纯投影 `normalizeWorkflowNotesCoverage`（`notes-v1`）：规范路径、文件哈希、带 `(source-file-sha256, line-index)` 身份的有序历史行、带逐行哈希的有序已接受 id、重复 id、计数与未接受尾部——可检视的事实而不是隐藏扫描。
