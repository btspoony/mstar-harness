- Added the file-native **workflow notes ledger** to the engine (`execution-ledgers.ts`): `appendWorkflowNote` appends ONE canonical `{version:1,id,workflowId,sessionId,kind:"note",ts,text}` line to `<control root>/workflows/<id>/notes.jsonl` under the maintenance exclusion and the per-workflow status lock, with C1's synchronous current-session assertion running as the last step before the `fsync`ed byte write (no `await` between them). The migrated `{kind:"note",ts,text}` lines and the inline PlanRow `notes` stay byte-for-byte preserved — nothing rewrites, reorders or compacts a retained ledger, and no note becomes a DB event.
- A record's identity is the caller's stable id: the same id with the same body replays without appending, the same id with a changed body refuses `execution-ledgers.id-conflict`, and an accepted id recorded twice refuses `execution-ledgers.ledger-foreign` instead of picking a winner. A crash-cut partial line of the very record being written is reconciled into exactly one accepted line; an unaccepted partial prefix that follows the record's own already accepted line is healed by removing that prefix only (the replay never re-appends the accepted line); an unterminated tail that is not that record's own partial refuses `execution-ledgers.tail-unreconciled` with every retained byte left in place.
- The retained leaf's trust decision IS its open: it is opened with `O_NOFOLLOW` and the same descriptor is re-verified (`fstat` — regular file, same device/inode as the bytes that were read), so a leaf swapped for a symlink, replaced or removed between the read and the commit refuses `execution-ledgers.target-replaced` instead of being followed, truncated or written through. Nothing is decided from an earlier `lstat` that a later open could contradict.
- Provenance is the bound session's own scope: the record's `workflowId`/`sessionId` are checked against the session the engine already authorizes — never inferred from a model-supplied field, a cached selection or the note body — and a mismatch refuses `execution-ledgers.scope-mismatch`. The append never materializes the control root or any authority file: an authorized current session may create its own workflow's retained **body dir** inside the lock (creating it only AFTER the current-session guard has authorized a genuinely absent one, so a stale, revoked or foreign session leaves no directory side effect), plus the one ledger line inside it; a symlinked/non-directory target or a non-regular ledger leaf refuses `execution-ledgers.target-untrusted`, so a write can never land through a link.
- Added the pure coverage projection `normalizeWorkflowNotesCoverage` (`notes-v1`) for the coverage producer: canonical path, file hash, the composition label (`absent` for no file vs `empty` for a present zero-byte file vs `legacy`/`versioned`/`unrecognized`/`mixed`), the ordered historical lines with their `(source-file-sha256, line-index)` identity, the ordered accepted ids with per-line hashes, duplicated ids, counts (including unrecognized lines) and the unaccepted tail — inspectable facts instead of a hidden scan that could only be told apart by a null hash.

- 为引擎新增**文件原生工作流笔记账本**（`execution-ledgers.ts`）：`appendWorkflowNote` 在 maintenance 排他锁与按工作流的 status 锁内，向 `<control root>/workflows/<id>/notes.jsonl` 追加**一条**规范化的 `{version:1,id,workflowId,sessionId,kind:"note",ts,text}` 行，且 C1 的同步当前会话断言是 `fsync` 字节写入之前的最后一步（两者之间无 `await`）。迁移产生的 `{kind:"note",ts,text}` 历史行与 PlanRow 内联 `notes` 保持逐字节不变——不重写、不重排、不压缩保留账本，笔记也绝不变成 DB 事件。
- 记录身份是调用方提供的稳定 id：同 id 同正文按重放处理、不追加；同 id 正文变更拒绝 `execution-ledgers.id-conflict`；同一已接受 id 出现两次拒绝 `execution-ledgers.ledger-foreign`，绝不在两个候选中挑一个。正在写入的记录自身的崩溃截断半行会被收敛为恰好一条已接受行；跟随在该记录**自身已接受行之后**的未接受半行前缀只删除该前缀（重放绝不重复追加已接受行），从而自愈；不是该记录自身前半段的未终止尾部拒绝 `execution-ledgers.tail-unreconciled`，且所有保留字节原样不动。
- 账本叶子的信任判定就是它的打开本身：以 `O_NOFOLLOW` 打开并对**同一 fd** 复核（`fstat`——普通文件、且 device/inode 与读到字节时一致），因此在读到字节与提交之间被换成符号链接、被替换或被删除的叶子以 `execution-ledgers.target-replaced` 拒绝，绝不被跟随、截断或写入。任何判定都不再来自随后可能被 open 推翻的早期 `lstat`。
- 出处即绑定会话自身的范围：记录的 `workflowId`/`sessionId` 与会话（引擎本就在授权的那一个）比对，绝不从模型字段、缓存选择或笔记正文推断；不一致拒绝 `execution-ledgers.scope-mismatch`。追加绝不物化控制根或任何权限文件：已授权的当前会话可在锁内创建其自身工作流的保留**body 目录**（仅在同步当前会话守卫确认目录确实缺失后才创建，因此过期、撤销或外来会话不会留下任何目录副作用），以及目录内的那一条账本行；符号链接/非目录目标或非普通文件账本叶子以 `execution-ledgers.target-untrusted` 拒绝，写入绝不会穿过链接落地。
- 为覆盖生产者新增纯投影 `normalizeWorkflowNotesCoverage`（`notes-v1`）：规范路径、文件哈希、组成标签（无文件为 `absent`，存在但零字节为 `empty`，以及 `legacy`/`versioned`/`unrecognized`/`mixed`）、带 `(source-file-sha256, line-index)` 身份的有序历史行、带逐行哈希的有序已接受 id、重复 id、计数（含不可识别行）与未接受尾部——可检视的事实，而不是只能靠空哈希区分的隐藏扫描。
