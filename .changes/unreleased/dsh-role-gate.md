- Added the **dispatch-role gate** (`roleGate`, default `hard`) at the subagent start seam: an explicit `Execute as:` / `Act as:` / `Role:` declaration — or a backticked/bold already-declared role id — in the Assignment header is normalized into the canonical Assignment header before the preset merge, so `rolePresets` and the fallbacks persona chain bind the role instead of silently starting a role-less child. Every `Execute as` header line is repaired with its label normalized (the parsers bind the LAST line, case-sensitively), and both candidate tiers are scanned on fence-masked text inside the Assignment header, so a role id quoted in a body sentence or a fenced block is never a repair candidate; a canonical declaration that exists only inside a fenced block is refused under `hard` (the header read is fence-unaware and the seam still binds that quote). `hard` refuses a start with no reliable declaration — or with two or more distinct ones, naming the ids and the exactly-one rule — with the exact fix and the mode-appropriate recovery (`warn` advises once per apply and suggests `off`); a role field that IS present but unusable (empty, or not a lowercase role id) gets its own cause-specific message naming the raw value and the accepted shape. `off` skips only the refusal, a single explicit declaration is still normalized. The non-harness exemption is judged at the child's EFFECTIVE start directory (absolute `cwd` used as-is, relative resolved against the parent's current directory, omitted inherited from it), and that parent directory is the working-directory projection the runtime itself resolves against — not the immutable `header.cwd` — so the default `subagent` / `spawn_teammate` starts are gated by the directory the parent is in NOW. Prompts that already carry a usable declaration, requests carrying `agentPreset`, and unknown providers pass through silently. A repair is reported only after the rewritten header is re-parsed with the same reader the preset merge uses: a declaration the rewrite cannot make that read bind (another `Execute as` line keeps winning) is refused under `hard` with its own cause and fix instead of being claimed as repaired.
- `roleGate` is one of the plugin's `volatile` config fields: it is read from the Loader's live config reference on every start, so the dsh plugin configuration form can edit it and the save (written into the profile patch) applies on the next subagent start without a reload.
- `dispatchBinding` defaults to `project-manager` — the harness model's only coordinating role — so a fresh deployment admits dispatches instead of refusing every one with `dispatch.anti-recursion.empty-binding` until the profile is hand-edited. It is a live `volatile` field too (editable in the plugin configuration form, applied on the next dispatch), the anti-recursion red line is untouched (an `Execute as` equal to the configured caller is still refused), and an explicitly blank binding still fails closed with a plugin warn that points at the settings form.
- Documented `roleGate` and the `dispatchBinding` default in the dsh README (EN/ZH) and the host dispatch reference.

- 在子代理启动缝隙新增**派发角色闸门**（`roleGate`，默认 `hard`）：Assignment 头部里显式的 `Execute as:` / `Act as:` / `Role:` 声明——或反引号/加粗的已声明角色 id——会在 preset 合并前被归一化为规范的 Assignment 头，使 `rolePresets` 与 fallbacks persona 链真正绑定角色，而不是静默启动无角色子代理。头部中每一条 `Execute as` 行都会被修复并归一化标签（解析器区分大小写且绑定**最后一条**）；两类修复候选都只在 Assignment 头部内的围栏掩码文本上扫描，因此正文语句或围栏代码块里引用的角色 id 永远不会成为候选；而只存在于围栏代码块中的规范声明在 `hard` 下会被拒绝（头部读取不识别围栏，缝隙仍会绑定该引用）。`hard` 拒绝没有可靠角色声明的启动——或存在两个及以上不同声明（消息点名这些 id 与"只能有一个"规则）——并给出确切修复与**与模式匹配**的恢复路径（`warn` 每次 apply 咨询一次且建议 `off`）；字段存在但值不可用（为空或不是小写角色 id）时给出独立的原因消息，点名原始值与合法形状。`off` 只跳过拒绝，单一显式声明仍会被归一化。非 harness 豁免按子代理**实际**启动目录判定（绝对 `cwd` 原样使用；相对 `cwd` 相对父目录当前目录解析；缺省 `cwd` 继承该目录），而父目录取运行时自身解析所用的 working-directory 投影，而非不可变的 `header.cwd`——因此默认的 `subagent` / `spawn_teammate` 启动按父代理**当前**所在目录受闸。已携带可用声明的 prompt、携带 `agentPreset` 的请求以及未知提供者一律静默直通。只有在重写后的头部用 preset 合并所用的同一读取器重新解析通过后，才会判定为"已修复"：重写无法让该读取绑定到的声明（另一条 `Execute as` 行仍然胜出）在 `hard` 下会以自身的原因与修复方案被拒绝，而不是被当作已修复。
- `roleGate` 是插件的 `volatile` 配置字段之一：每次启动都从 Loader 的实时配置引用读取，因此 dsh 插件配置页可编辑它，保存（写入 profile patch）在下一次子代理启动即生效，无需重载。
- `dispatchBinding` 默认 `project-manager`——harness 模型中唯一的协调角色——因此新部署开箱即可派发，而不会在操作者手改 profile 之前以 `dispatch.anti-recursion.empty-binding` 拒绝每一次派发。它同样是实时的 `volatile` 字段（可在插件配置页编辑，下一次派发即生效）；反递归红线不变（`Execute as` 等于所配置 caller 时仍被拒绝），显式置空的绑定仍然 fail-closed，并在 apply 时记录一条指向配置页的 warn。
- 在 dsh README（中英）与 host 派发参考文档中记录 `roleGate` 与 `dispatchBinding` 默认值。
