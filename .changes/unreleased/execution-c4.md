- The CLI now speaks the ACTIVE execution transport of contract §3.2 in production code, not just in helpers: `packages/cli/src/execution-session.ts` owns the independently acquired caller identity (`MSTAR_EXECUTION_IDENTITY`, decoded as the engine's canonical `serializeExecutionValue(identity)` and validated by the shared `validateExecutionIdentity`), the `--session-ref` wire, the full-execution-token `--expect`, the local launcher `mstar session run --workflow W --role coordinator|plan-pm [--plan P] [--harness H] -- <argv>` (mints one local identity, overwrites the channel, deletes the legacy one, inherits stdio, propagates the child's exit code and re-raises the signal it was killed by), and `mstar session recover` (the active coordinator recovery, naming the prior holder or `--unowned`).
- `mstar plan` carries both transports disjointly: `--session` runs the unchanged pre-activation file call, while `--session-ref` + a FULL `--expect` + `--operation` runs the landed DB verbs (`bindExecutionSession`, `mutateExecutionPlan`, `readExecutionPlan`, `resumeExecutionSession`) under the acquired identity. A mixed invocation, a partial active flag set, a numeric execution expectation and `--session-id` on the active route are usage refusals (exit 2) decided before any IO; the engine's own codes and exit 1 stay untouched, and a legacy `--expect` revision is never coerced into a token.
- `packages/cli/src/execution-workflow.ts` routes the direct `index.ts` workflow writers through the landed DB verbs: `workflow register` / `iteration register` publish through `commitExecutionRegistration` with the catalog delta derived exactly as the file journal derives it (and the P2-resolved iteration plan pointers), `workflow evidence` records the `delivery` transition, and `status workflow-close` performs the terminal `lifecycle` transition — no file close, no unregister step and no `--ended-at` rewrite survive on the active route. The closed workflow grammar (`phase`, `lifecycle`, `execution-policy`, `integration-worktree`) joins the existing `mstar workflow` group, and the retired forms (file close, one-time `--declare-kind`, structural `amend-prepare`) refuse `execution.consumer-not-ready` instead of writing retired bytes.
- `status validate` reports the root and per-workflow execution tokens the active writes consume as their CAS, so a caller passes `--expect` from a read instead of inventing one.
- New regressions: `execution-session.test.ts` (documented invocations, launcher exit/signal propagation, the bind → resume → mutation chain with an exact-replay retry, a copied/foreign identity, mixed transports, active recovery with a real stop attestation) and `execution-workflow.test.ts` (trusted registration, the named lifecycle/policy/delivery transitions, the iteration integration checkout, stale/foreign/mixed refusals with no mutation, terminal atomicity, retired forms), plus the `execution transport` group in `plan-coordination.test.ts` for the disjointness matrix and the engine's own not-active refusal.

- CLI 现在以生产代码实现契约 §3.2 的 **active** 执行传输（不再只是 helper）：`packages/cli/src/execution-session.ts` 承载独立获取的调用者身份（`MSTAR_EXECUTION_IDENTITY`，按引擎 canonical `serializeExecutionValue(identity)` 解码并由共享 `validateExecutionIdentity` 校验）、`--session-ref` wire、完整执行令牌 `--expect`、本地启动器 `mstar session run --workflow W --role coordinator|plan-pm [--plan P] [--harness H] -- <argv>`（铸造一个本地身份、覆写该通道、删除 legacy 通道、继承 stdio、传递子进程退出码并在子进程被信号杀死时重新抛出同一信号）以及 `mstar session recover`（active 协调者恢复，须指名前持有者或显式 `--unowned`）。
- `mstar plan` 严格分离两条传输：`--session` 走未改动的 pre-activation 文件调用；`--session-ref` + 完整 `--expect` + `--operation` 在已获取身份下走已落地的 DB 动词（`bindExecutionSession`、`mutateExecutionPlan`、`readExecutionPlan`、`resumeExecutionSession`）。混合调用、active 旗标不全、数字型执行期望以及 active 路由上的 `--session-id` 都在任何 IO 之前按 usage 拒绝（exit 2）；引擎自身的错误码与 exit 1 不变，legacy 的 `--expect` revision 绝不被强转为 token。
- `packages/cli/src/execution-workflow.ts` 把 `index.ts` 的直接 workflow 写入入口接到已落地的 DB 动词：`workflow register` / `iteration register` 通过 `commitExecutionRegistration` 发布（catalog delta 与文件 journal 的推导完全一致，并消费 P2 解析后的 iteration plan 指针），`workflow evidence` 记录 `delivery` 转换，`status workflow-close` 执行终止 `lifecycle` 转换——active 路由上不再保留文件 close、unregister 步骤与 `--ended-at` 覆写。封闭的 workflow 语法（`phase`、`lifecycle`、`execution-policy`、`integration-worktree`）加入既有的 `mstar workflow` 组；退役形态（文件 close、一次性 `--declare-kind`、结构性 `amend-prepare`）以 `execution.consumer-not-ready` 拒绝，而不是写入退役字节。
- `status validate` 报告 active 写入用作 CAS 的 root 与逐 workflow 执行令牌，使调用者从一次读取获得 `--expect`，而不必自行编造。
- 新增回归：`execution-session.test.ts`（文档化调用、启动器退出/信号传递、bind → resume → mutation 链路与精确重放重试、被复制/异域身份、混合传输、带真实停止断言书的 active 恢复）与 `execution-workflow.test.ts`（可信注册、命名的 lifecycle/policy/delivery 转换、iteration 集成检出、无写入的 stale/异域/混合拒绝、终止原子性、退役形态），并在 `plan-coordination.test.ts` 增加 `execution transport` 组覆盖互斥矩阵与引擎自身的 not-active 拒绝。
