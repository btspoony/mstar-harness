- Made admission cost proportional to contention (**fixes #308, claim half**): the pre-activation plan bind now has a **claim bootstrap**. `mstar plan bind --assignment <absolute-md-path>` on an unclaimed, unprepared `Todo`/`Blocked` row (no `coordination.session`, no handoff, no lease) writes the row's plan-pm session binding and emits the session envelope, claims **no** lease and leaves the status untouched — so an agent that finds a row nobody has prepared can start from the Assignment it was handed instead of waiting on the coordinator seat. A second claim on the claimed row is `coordination.duplicate-holder`, and the locator-less `--workflow/--plan` form keeps its `coordination.not-prepared` refusal unchanged.
- `prepare` gained exactly one seat: the plan session the addressed row is itself bound to — the claim's own claimant — while that row is still unprepared. It is proved against the row under the snapshot lock (session id **and** canonical envelope file), so a leaf, foreign or other-session identity keeps the existing `coordination.session-role` refusal, and the coordinator seat is unchanged. The same session then binds again to claim the lease (same identity, same envelope) and the row reaches `InProgress`.
- `plan show` advertises `prepare` to that claimant on its claimed-but-unprepared row, and `skills/mstar-iteration/references/plan-scoped-pm.md` §1/§2/§4.1/§6 plus `commands/iteration-drive.md`'s scoped-route row describe the chain (claim → prepare → bind) and the locator-only rule.
- Made admission cost proportional to contention (**fixes #308, adoption half**): a `bind` on a prepared row **nobody else holds** (no `coordination.session` at all, or the binder's own claim binding — the D0 claim row — and no `coordination.handoff`) whose addressed Assignment bytes changed after `prepare` no longer hard-stops. The bind refreshes the row's pin to the bytes it actually bound and appends one `coordination.self_amendments` entry to the workflow snapshot — `{at, session_id, old_sha256, new_sha256, operation_id, prepared_by_matches?}` — in the same locked write, then continues as a normal bind. A row held or handed off by **another** session keeps the terminal `coordination.assignment-stale`, a missing Assignment is never adopted, and the decision rests on the row's unclaimed state alone: the file route's `--session-id` is caller-asserted, so no `prepared_by === caller` gate exists.
- Added the append-only `coordination.self_amendments` audit to the snapshot schema and its strict validator (exact keys, bare sha256 digests, boolean annotation) beside `identity_recoveries`; the record is provenance only — nothing in the engine reads it to decide anything and no gate may be derived from it. A workflow whose snapshot carries no `coordination` block (reachable now that the claim bootstrap needs no coordinator seat) refuses the amendment rather than refreshing a pin unrecorded. The coordinator is the post-hoc verifier: `skills/mstar-iteration/references/plan-scoped-pm.md` §2/§2.5/§6 document reading it (and the row's `prepared_by` / session binding) before `accept`.
- The audit survives minimal DB import: `execution-import-rows` projects both `coordination.self_amendments` and `coordination.identity_recoveries` into the imported workflow header, preserving each record verbatim.

- 让准入成本与争用程度成正比（**修复 #308 的 self-claim 一半**）：pre-activation 的 plan bind 新增 **claim bootstrap**。在无人认领且尚未 prepared 的 `Todo`/`Blocked` 行上（无 `coordination.session`、无 handoff、无 lease），`mstar plan bind --assignment <绝对 md 路径>` 写入该行的 plan-pm session 绑定并生成 session envelope，**不**取 lease、不改行状态——因此拿到 Assignment 的 agent 可以直接开工，不必等 coordinator 席位。对已 claim 的行再次 claim 为 `coordination.duplicate-holder`；无 locator 的 `--workflow/--plan` 形态保持原有的 `coordination.not-prepared` 拒绝不变。
- `prepare` 只新增一个合法席位：该行自身绑定的那个 plan session（claim 的 claimant），且该行仍未 prepared。该身份在快照锁内对行校验（session id **与** canonical envelope 文件），因此 leaf / foreign / 其他 session 身份保持既有 `coordination.session-role` 拒绝，coordinator 席位行为不变。同一 session 随后再次 bind 以取得 lease（同一身份、同一 envelope），行进入 `InProgress`。
- `plan show` 会向该 claimant 在“已 claim 未 prepared”的行上宣告 `prepare`；`skills/mstar-iteration/references/plan-scoped-pm.md` §1/§2/§4.1/§6 与 `commands/iteration-drive.md` 的 scoped route 行同步描述该链路（claim → prepare → bind）与 locator-only 规则。
- 让准入成本与争用程度成正比（**修复 #308 的 adoption 一半**）：当 bind 面对一个 **非他人持有**（完全无 `coordination.session`，或该 session 就是 binder 自己的 claim 绑定——即 D0 claim 行；且无 `coordination.handoff`）且其 addressed Assignment 在 `prepare` 之后被改动的已 prepare 行时，不再硬停。该 bind 会在同一次加锁写入中把该行 pin 刷新为它实际绑定的字节，并向 workflow 快照追加一条 `coordination.self_amendments` 记录——`{at, session_id, old_sha256, new_sha256, operation_id, prepared_by_matches?}`——随后继续正常 bind。被**其他** session 持有或已 handoff 的行保持终态 `coordination.assignment-stale`，Assignment 不存在时绝不 adopt；判定不对调用方做认证：文件路线的 `--session-id` 由调用方自述，因此不存在 `prepared_by === caller` 门禁，他人的 session id 仍然只得到原有拒绝。
- 在快照 schema 中新增仅追加的 `coordination.self_amendments` 审计及其严格校验器（键集固定、裸 sha256、布尔注解），与 `identity_recoveries` 并列；该记录只是存证——引擎不读取它做任何决定，也不得由它派生门禁。若 workflow 快照没有 `coordination` 块（claim bootstrap 不需要 coordinator 席位，因此该状态可达），则不做无法留痕的刷新，而是以 `coordination.assignment-stale` 拒绝并提示先绑定该 workflow 的 coordinator 席位。coordinator 是事后验证者：`skills/mstar-iteration/references/plan-scoped-pm.md` §2/§2.5/§6 描述在 `accept` 之前读取它（以及该行的 `prepared_by` / session 绑定）。
- 最小 DB 导入会保留该审计：`execution-import-rows` 将 `coordination.self_amendments` 与 `coordination.identity_recoveries` 原样投影到 workflow header。
