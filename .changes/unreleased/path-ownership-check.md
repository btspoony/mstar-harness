- Added **`mstar path check [path]`**: read-only, Git-verdict-driven path-ownership check (exit `0` clean, `1` findings). Whether a path is ignored decides its owner, not its name: an ignored path outside the control checkout is `path.process-outside-control`, a committable path outside the caller's own checkout is `path.result-outside-worktree`, and a verdict Git cannot answer is `path.unverifiable` — all findings. The tracked-result domains (`specs` / `knowledge` / `adr`) also earn a **warning** rather than a failure when Git ignores them (`path.result-ignored`, exit `0`): the content can never be committed or shared, so a fully gitignored `.mstar/specs` correctly kept in the control checkout reports clean plus a warning pointing at `.agents/` or `.mstarc`. With no argument the envelope reports `trackedHarness` and `processHarness` separately, with `findings` and `warnings` kept apart; with a `path` it probes that one target under the same rules.
- **engine**: `resolveSpecsDir` gains `.agents/specs` between the harness dir and `docs/specs` (the full chain is now `.mstarc` `specs_dir` → `{HARNESS_DIR}/specs` → `.agents/specs` → `docs/specs` → root `specs` → legacy `designs`); `resolveKnowledgeDir` gains an `.agents/knowledge` candidate; new `resolveAdrDir` resolves `.mstarc` `adr_dir` → `{HARNESS_DIR}/adr` → `.agents/adr` → `docs/adr`. `.mstarc` gains the `adr_dir` key (`MstarcStringKey` `adrDir`). A repo whose `.mstar/` is gitignored wholesale can now resolve its tracked results under `.agents/`. The canonical `.gitignore` snippets re-include `adr/` symmetrically with specs and knowledge (`!.mstar/adr/` + `!.mstar/adr/**`, and the `.agents` pair), so a scaffolded repo can commit ADRs; an author-declared `.gitignore` is still left untouched.
- **cli**: `mstar path resolve` prints `knowledgeDir` and `adrDir` alongside the existing dirs.
- Updated `mstar-conventions` (`{ADR_DIR}` symbol, the `.mstarc` `adr_dir` key, the specs/knowledge/adr resolution chains, the fully-gitignored `.agents/` rule and `mstar path check`), its `references/artifact-storage-paths.md`, `mstar-use-cli/references/checks-and-lints.md`, `mstar-artifacts/references/knowledge-and-designs.md`, and `docs/runtime-reference.md`.

- 新增 **`mstar path check [path]`**：只读、按 Git 实况判定的路径归属检查（exit `0` 干净、`1` 有 findings）。判定所有者的是「是否被忽略」而非目录名：被忽略的路径落在 control checkout 之外报 `path.process-outside-control`，可提交的路径落在调用方自己的 checkout 之外报 `path.result-outside-worktree`，git 无法给出结论报 `path.unverifiable`——三者都是 finding。tracked 结果域（`specs` / `knowledge` / `adr`）被 Git 忽略时只产生 **warning** 而非失败（`path.result-ignored`，exit `0`）：这类内容永远无法提交或共享，因此被全量 gitignore 的 `.mstar/specs` 只要正确留在 control checkout 就是「干净 + warning」，warning 指向 `.agents/` 或 `.mstarc`。不带参数时 envelope 分别报告 `trackedHarness` 与 `processHarness`，且 `findings` 与 `warnings` 分开；带 `path` 时按同样规则只核该目标。
- **engine**：`resolveSpecsDir` 在 harness 目录与 `docs/specs` 之间新增 `.agents/specs`（完整链：`.mstarc` `specs_dir` → `{HARNESS_DIR}/specs` → `.agents/specs` → `docs/specs` → 根 `specs` → legacy `designs`）；`resolveKnowledgeDir` 新增 `.agents/knowledge` 候选；新增 `resolveAdrDir`，链为 `.mstarc` `adr_dir` → `{HARNESS_DIR}/adr` → `.agents/adr` → `docs/adr`。`.mstarc` 新增 `adr_dir` 键（`MstarcStringKey` `adrDir`）。`.mstar/` 被全量 gitignore 的仓库因此可在 `.agents/` 下解析 tracked 结果。canonical `.gitignore` snippet 现在与 specs、knowledge 对称地重新包含 `adr/`（`!.mstar/adr/` + `!.mstar/adr/**`，`.agents` 侧同理），scaffold 出的仓库因此可以提交 ADR；已由作者声明的 `.gitignore` 仍保持原样不动。
- **cli**：`mstar path resolve` 输出新增 `knowledgeDir` 与 `adrDir`。
- 更新 `mstar-conventions`（`{ADR_DIR}` 符号、`.mstarc` `adr_dir` 键、specs/knowledge/adr 解析链、harness 根全量忽略时的 `.agents/` 规则与 `mstar path check`）、其 `references/artifact-storage-paths.md`、`mstar-use-cli/references/checks-and-lints.md`、`mstar-artifacts/references/knowledge-and-designs.md` 与 `docs/runtime-reference.md`。
