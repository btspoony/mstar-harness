- **dsh publishes three native tools again; every other mstar command is an MCP family action.** The native surface drops from fifteen tools to three and keeps only what the scoped MCP route cannot do — `mstar_plan_bind` (the sole writer of the dsh-local durable `executionBinding` slot and its adoption receipt), `mstar_audit_validate` (the review-report credential scan, which no `mstar_audit` action publishes) and `mstar_execution_clear` (no shared `execution.clear` command). The twelve removed mirrors duplicated an MCP tool 1:1 and cost ~10k characters of fixed context per request; the earlier `dsh native-command-surface` fragment's named-writable set is superseded by this one. **One exception to the 1:1 claim:** the removed compound-validate mirror also published a dsh-only `repo_root` reference-existence check that `compound.validate` does not carry, so that capability has no MCP twin (it belongs to the `mstar-compound-refresh` write seam).
- **Holding an old tool name?** There is no alias and no compatibility tool, and none is planned: call the folded family instead — `mcp__mstar__mstar_<family>` with the matching `action` (the old `mstar_plan_prepare` spelling becomes `mstar_plan` + `action: "prepare"`, and so on) — and read a family's real actions and fields with `mcp__mstar__mstar_schema` (`family: <name>`, or `command: <family>.<action>` for one leaf contract). Across the MCP server the same fold took `tools/list` from 113 tools / 173,340 characters of description plus input schema to 33 tools / 31,209 characters.
- **The model-facing `<mstar_engine_status>` row is one delta line.** Measured on the richest payload: 899 characters / 15 lines → 212 characters / 3 lines. It carries the selected workflow, its non-Done plans, the branch anchors and the phase-gate verdict; the residuals rollup, branch policy, spec-integration anchor, plan row scopes, knowledge digest, compass direction and agent-flow ledger are payload-only (the panel renders them) and stay readable from the engine authorities. The always-on system-prompt digest keeps the version, the active workflow, its non-Done plans, the branch anchors and the gate verdict, so a row-less step is never factless.
- **Skill descriptions are trigger contracts again.** All 24 `skills/*/SKILL.md` frontmatter descriptions were cut from 11,281 characters to 4,242 (longest file 932 → 198) by removing methodology summaries, phase lists and path enumerations the body already owns — every trigger word that makes a skill discoverable is kept. The dsh Agent Teams reference now also states the report budget: durable conclusions live in files, a teammate reply is status + artifact path + a short summary under ~15 lines / ~1,200 characters, because the lead re-reads every reply on every later turn of its session (measured: 110 replies / 240k characters in one session).

- **dsh 重新只发布三个原生工具，其余 mstar 命令都走 MCP 家族 action。** 原生面从十五个工具降到三个，只保留 scoped MCP 路线做不到的事——`mstar_plan_bind`（dsh 本地持久 `executionBinding` 槽及其采纳收据的唯一写入者）、`mstar_audit_validate`（评审报告凭据扫描，`mstar_audit` 家族没有任何 action 提供）与 `mstar_execution_clear`（不存在共享的 `execution.clear` 命令）。被移除的十二个镜像与 MCP 工具 1:1 重复，每个请求固定消耗约 10k 字符上下文；早先 `dsh native-command-surface` 片段列出的「具名可写工具集」由本条取代。**「1:1」有一处例外：**被移除的 compound-validate 镜像还发布了一个 dsh 独有的 `repo_root` 引用存在性检查，`compound.validate` 并不携带它，这项能力因此没有 MCP 对应物（它属于 `mstar-compound-refresh` 的写入 seam）。
- **手里还握着旧工具名？** 没有别名、没有兼容工具，也不计划提供：改调折叠后的家族——`mcp__mstar__mstar_<family>` 配对应 `action`（旧的 `mstar_plan_prepare` 即 `mstar_plan` + `action: "prepare"`，其余同理）——并用 `mcp__mstar__mstar_schema`（`family: <name>`，或单个叶子契约的 `command: <family>.<action>`）读取家族真实的 action 与字段。同一折叠在整个 MCP 服务器上把 `tools/list` 从 113 个工具 / 173,340 字符描述加输入 schema 降到 33 个工具 / 31,209 字符。
- **模型可见的 `<mstar_engine_status>` 行合并为一条 delta 行。** 在最丰富的 payload 上实测：899 字符 / 15 行 → 212 字符 / 3 行。行内携带选中的工作流、其非 Done plans、分支锚点与相位闸门判定；residuals 汇总、branch policy、spec 集成锚点、plan 行 row scope、知识摘要、compass 方向与 agent-flow ledger 改为 payload-only（由面板渲染），并仍可从 engine 权威读取。常驻 system prompt 摘要保留版本、活动工作流、其非 Done plans、分支锚点与闸门判定，因此没有该行的步骤也不会缺少这些事实。
- **技能描述回归触发契约。** 24 个 `skills/*/SKILL.md` frontmatter 描述从 11,281 字符压到 4,242（最长文件 932 → 198）：删掉正文已承担的方法学摘要、阶段清单与路径枚举，保留每一个让技能可被发现的路由词。dsh Agent Teams reference 同时写清报告预算：持久结论落文件，teammate 回复只带状态 + 产物路径 + 简短摘要且控制在约 15 行 / 1,200 字符以内，因为 lead 在会话的每一个后续 turn 都会重读每条回复（实测：单会话 110 条回复 / 240k 字符）。
