- Gave every new agent-flow ledger row a **stable record identity built from verified native facts**: durable workflow events carry `eventId` + the source position `{sessionId, streamId, seq}`, where `streamId` is the log's VERIFIED incarnation (derived from the log's immutable head — never the store epoch, never a file mtime) and the id names the session AND the incarnation, so neither a session cross nor a rebuilt log can collide. Live tool-call rows carry `wfc1:<sessionId>:<callId>:<kind>` only when the seam supplies BOTH the carrying session id and a call id — an exec-less or call-less row records without an id instead of emitting `wfc1::`. A session whose log head cannot be read records nothing: no incarnation is invented.
- Made the durable **accepted-identity index** (`agent-flow-ids.jsonl`, one fsynced line per accepted row) the dedup authority, and reduced the cursor sidecar (`workflow-ledger-cursors.json`, v2 `{next, stream}` with v1 read compatibility) to a per-incarnation scan bound. A MISSING index is a legitimate first run only while no retained history chunk holds an index-scoped (`wfe1:`) accepted row — a history of only live tool-call rows (`wfc1:`, never indexed) or legacy rows still proceeds, while an unreadable or damaged history fails closed instead of reading as "no history"; once an index-scoped row has been archived its entry is required, so a missing index refuses instead of re-appending. Two index entries for one record id with contradictory digests also refuse rather than being resolved to the first, while an identical repeat is accepted unchanged. A rebuilt log is scanned from its own floor instead of being skipped by a stale session bound, and an archived or cursor-evicted accepted row is still recognized instead of being appended twice.
- Kept the append, the identity commit and the scan-bound advance in ONE shared-lock critical section (`recordWorkflowEvent`): a crash between them replays into the found id. Display compaction is now ONE transaction recorded in the transient `agent-flow-compaction.json` journal (`tailBefore`/`tailAfter` full-file sha256 + the exact archive range + the removed line count): the record is durable before the archive is touched, the archive before the tail is replaced, and the record is durably removed only once the range is provably complete. Every write path resolves an unfinished transaction first (so a later compaction can never pass an unfinished one), a tail matching neither state — or a matching after-state with an incomplete archive range — is refused rather than guessed, a missing chunk is only created at offset 0, an existing partial prefix is truncated and replayed only when it is byte-for-byte this transaction's own prefix, and coverage/backup entries refuse while the journal exists. The durable order inside the single critical section is fsync-enforced — ledger row (fsynced append, compacted tail replaced through a fsynced temp + atomic rename + fsynced directory) → identity-index entry (fsynced) → cursor (durable atomic replace with a fsynced temp and directory) — and an unreadable archive chunk, a malformed cursor entry, an un-stamped legacy bound that would shorten a walk, and a live tool-call row arriving while the index is unreadable are all refused rather than downgraded. A PRESENT-but-unreadable cursor or index, a failed identity commit, and a reused identity with different bytes are ADVISORY REFUSALS — no append, no bound advance, and never "accepted" from an unreadable authority.
- Both agent-flow write paths (`recordWorkflowEvent` and the live tool-call append) now take the §4.3 execution-maintenance exclusion (`<harnessDir>/.execution-maintenance/.status-write.lockdir`, the engine's key spelling, no engine import) BEFORE the per-workflow lock, so a plugin write is refused — advisably — inside an activation/restore/migration window instead of landing in a directory that is being rewritten; `EXECUTION_MAINTENANCE_LOCKDIR` and the synchronous `withExecutionMaintenanceLock(harnessDir, fn, opts?)` are exported for the selection owner to share the same key, and `awaitWorkflowLedgerIdle` is now test-runner-gated like the engine's seams.
- Separated the bounded display tail from dedup retention: evicted lines are archived byte-exact into `fsync`ed sealed chunks under `<workflowDir>/agent-flow-history/` (`chunk-NNNNNN.jsonl`, inventoried by `listAgentFlowHistoryChunks`) BEFORE the 500-event tail is rewritten, retried batches are merged by byte overlap so an accepted occurrence is never archived twice, and only rows whose identity is already durable are evicted.

- 为每条新的 agent-flow 账本行引入 **由可验证原生事实构建的稳定记录身份**：持久工作流事件带 `eventId` 与来源位置 `{sessionId, streamId, seq}`，其中 `streamId` 是日志的**已核实化身**（由日志不可变头部推导——绝不是 store epoch，也不是文件 mtime），且 id 同时包含会话与化身，因此跨会话与重建日志都不会碰撞。实时工具调用行仅在同一次观测同时拿到承载会话 id 与 call id 时才带 `wfc1:<sessionId>:<callId>:<kind>`——无 exec/无 callId 的行只记录不带身份，绝不再发 `wfc1::`。日志头部不可读的会话不写入任何行：不臆造化身。
- 把**持久化接受身份索引**（`agent-flow-ids.jsonl`，每条已接受行一行且 `fsync`）作为去重权威，游标旁车（`workflow-ledger-cursors.json`，v2 `{next, stream}`，兼容读取 v1）缩减为按化身的扫描下界。 索引缺失只有在保留历史中不存在**索引范围（`wfe1:`）**的已接受行时才算合法首跑——仅含实时调用行（`wfc1:`，从不入索引）或 legacy 行的历史仍可正常记录，而历史不可读或受损时 fail closed，绝不当作“无历史”；一旦索引范围的已接受行已归档，其条目即为必需，缺失索引时拒绝而不是重新追加。同一记录 id 出现互相矛盾的 digest 时拒绝，而不是取首条；同 id 同 digest 的重复按一致重复接受且不改字节。重建日志从自身下界开始扫描，不再被过期的会话下界跳过；已归档或游标被淘汰的已接受行仍能被识别，不会被重复追加。
- 追加、身份提交与扫描下界推进仍在同一个共享锁临界区（`recordWorkflowEvent`）内完成：三者之间崩溃都会重放并命中已存在 id。存在但不可读的游标或索引、身份提交失败、以及字节不同的重用身份，都是 advisory 拒绝——不追加、不推进下界，且绝不把不可读权威当作 accepted。
- 展示压缩现在是一个记录在**瞬态** `agent-flow-compaction.json` journal 中的事务（`tailBefore`/`tailAfter` 整文件 sha256 + 精确归档区间 + 被移除行数）：记录先于触碰归档持久化、归档先于替换尾部持久化、只有区间可证完整后才 durable 删除记录。每条写路径先解析未完成事务（后续压缩不可能越过未完成者）；既不匹配 before 也不匹配 after 的尾部（或匹配 after 但归档区间不完整）一律拒绝而非猜测；缺失 chunk 仅在 offset 0 时创建；已存在的部分前缀只有在逐字节等于本事务自身前缀时才允许裁掉重放；journal 存在期间覆盖/备份入口拒绝。
- 两条 agent-flow 写路径（`recordWorkflowEvent` 与实时工具调用追加）现在都会在取 per-workflow 锁**之前**先取 §4.3 的 execution-maintenance 排他（`<harnessDir>/.execution-maintenance/.status-write.lockdir`，沿用 engine 的键拼写、不引入 engine import），因此在激活/恢复/迁移窗口内插件写入会被**拒绝**（advisory），而不会落进正在被重写的目录；同时导出 `EXECUTION_MAINTENANCE_LOCKDIR` 与同步 `withExecutionMaintenanceLock(harnessDir, fn, opts?)` 供选择权 owner 共用同一把键，`awaitWorkflowLedgerIdle` 改为与 engine 相同的 test-runner 门控。
- 有界展示尾部与去重保留分离：在重写 500 事件尾部之前，被淘汰行先逐字节写入 `fsync` 过的密封分块 `<workflowDir>/agent-flow-history/chunk-NNNNNN.jsonl`（由 `listAgentFlowHistoryChunks` 清点）；崩溃重试按字节重叠合并，保证同一已接受事件不会被归档两次；只有身份已持久的行才会被淘汰。
