- Added the optional Assignment field **`Write domain: control`** (`control` | `work`; absent = `work`) with its companion **`Control write paths`** listing the actual process targets the Assignment writes (absolute, or resolved against `Worktree path`; a trailing `/` declares a directory explicitly, so Git directory rules such as `!.mstar/notes/` apply, while any other entry is verified under **both** file and directory ignore rules and must be ignored in both — a file-path-only probe approves a location whose directory contents are still committed, e.g. `.mstar/notes` under `.mstar/**` + `!.mstar/notes/` + `!.mstar/notes/**`, so either committable shape refuses the target as `dispatch.control-write.target-committable`; `.mstar/plans/run.md` is ignored in both shapes under `.mstar/**`). An Assignment that writes only the control checkout's gitignored process targets may name `Worktree path` = control root with `Working branch` set to the branch that checkout currently has checked out (e.g. `main` on a default-main repo — `main` is an example, never a literal instruction) and is exempt from default-branch protection; all three branch forms stay valid, including `Branch policy: direct on <branch> — <reason>`. `mstar dispatch validate` verifies the worktree path equals the control root, the declared branch (any of the three forms) equals its checked-out branch, and probes **every declared target**: each must be Git-ignored in both shapes (a trailing `/` probes the directory only) and inside the control root — a repo whose `.gitignore` covers only `.mstar/plans/` passes for a target under `plans/`, while declaring a tracked target such as `.mstar/specs/…` is refused. Refusals are `dispatch.control-write.control-root-unresolved`, `dispatch.control-write.worktree-not-control`, `dispatch.control-write.branch-mismatch`, `dispatch.control-write.target-committable`, `dispatch.control-write.target-outside-control` and `dispatch.control-write.target-unverifiable`, each naming a recovery. The same validation now runs in the shared host dispatch gate (`composeDispatchGate`, OpenCode v2 / dsh / omp hard enforcement), so a host hard gate cannot be bypassed by declaring the field; an unverifiable control root keeps the dispatch refused with its recovery.
- **engine**: `parseAssignmentFields` parses `Worktree path` / `Write domain` / `Control write paths` through the same header grammar; `validateAssignmentFields` reports `assignment.field.write-domain-unknown`, `assignment.field.control-write-missing-worktree`, `assignment.field.control-write-missing-branch` and `assignment.field.control-write-paths-missing`; `dispatch.validate` and `composeDispatchGate` share `validateControlWriteAssignment`, which resolves the control root via `readMainWorktree`, requires `Worktree path` to equal it, compares the declared branch (any of the three forms) with its checked-out branch, and probes every declared target via `probePathOwnership` (a trailing `/` probes the directory only; every other entry is probed as both file and directory, and either committable shape refuses it); both skip `assertDefaultBranchProtected` for control-domain text, and an unresolvable control root or Git probe failure stays a refusal with a recovery rather than a silent pass.
- **cli**: `mstar dispatch validate` accepts a control-domain Assignment on `main` and prints the new refusal codes with their recovery.
- Updated `mstar-branch-worktree` (control-domain write subsection), `mstar-dispatch-gates` (Assignment field list) and `mstar-roles/references/project-manager/dispatch-and-assignment.md` (template + field table).

- 新增可选 Assignment 字段 **`Write domain: control`**（取值 `control` | `work`；缺省 `work`）及其配套字段 **`Control write paths`**：列出该 Assignment 实际写入的过程目标（绝对路径，或相对 `Worktree path` 解析；结尾的 `/` 显式声明目录，因此适用 Git 目录规则如 `!.mstar/notes/`；其余条目**同时**按文件与目录两条规则核验，**两种形状都必须被忽略**——只按文件探测会放过目录内容仍会提交的位置，例如 `.mstar/**` + `!.mstar/notes/` + `!.mstar/notes/**` 下的 `.mstar/notes`，因此任一形状会提交即按 `dispatch.control-write.target-committable` 拒绝；`.mstar/plans/run.md` 在 `.mstar/**` 下两种形状都被忽略）。只写控制检出 gitignored 过程目标的 Assignment 可写 `Worktree path` = 控制根、`Working branch` = 该检出**当前检出**的分支（默认 `main` 的仓库即 `main`；`main` 只是示例，不是字面指令），并豁免默认分支保护；三种分支写法仍全部有效，含 `Branch policy: direct on <branch> — <reason>`。`mstar dispatch validate` 核验 worktree 路径等于控制根、声明的分支（三种写法任一）等于其当前检出分支，并**逐个探测声明的目标**：每个目标必须在两种形状下都被 Git 忽略（结尾带 `/` 的只探目录）且位于控制根内——仓库只忽略 `.mstar/plans/` 时，声明 `plans/` 下的目标即通过；声明被跟踪的目标（如 `.mstar/specs/…`）会被拒。拒绝码为 `dispatch.control-write.control-root-unresolved`、`dispatch.control-write.worktree-not-control`、`dispatch.control-write.branch-mismatch`、`dispatch.control-write.target-committable`、`dispatch.control-write.target-outside-control` 与 `dispatch.control-write.target-unverifiable`，各带明确修复路径。同一核验现已进入共享宿主 dispatch 门禁（`composeDispatchGate`，OpenCode v2 / dsh / omp 的 hard enforcement）——宿主硬门禁不能靠声明该字段绕过；控制根不可核验时 dispatch 仍然被拒，并附修复路径。
- **engine**：`parseAssignmentFields` 用同一 header 语法解析 `Worktree path` / `Write domain` / `Control write paths`；`validateAssignmentFields` 报 `assignment.field.write-domain-unknown`、`assignment.field.control-write-missing-worktree`、`assignment.field.control-write-missing-branch` 与 `assignment.field.control-write-paths-missing`；`dispatch.validate` 与 `composeDispatchGate` 共用 `validateControlWriteAssignment`：通过 `readMainWorktree` 解析控制根、要求 `Worktree path` 等于控制根、把声明的分支（三种写法任一）与控制检出当前分支比对，并用 `probePathOwnership` 逐目标探测（结尾带 `/` 只探目录，其余同时按文件与目录探测，任一形状可提交即拒）；两者都对控制域文本跳过 `assertDefaultBranchProtected`，控制根不可解析或 Git 探测失败仍是带修复路径的拒绝，绝不静默放行。
- **cli**：`mstar dispatch validate` 接受 `main` 上的控制域 Assignment，并以拒绝码 + 修复路径报出新失败。
- 更新 `mstar-branch-worktree`（控制域写入小节）、`mstar-dispatch-gates`（Assignment 字段清单）与 `mstar-roles/references/project-manager/dispatch-and-assignment.md`（模板 + 字段表）。
