- Added the optional Assignment field **`Write domain: control`** (`control` | `work`; absent = `work`) with its companion **`Control write paths`** listing the actual process targets the Assignment writes (absolute, or resolved against `Worktree path`). An Assignment that writes only the control checkout's gitignored process targets may name `Worktree path` = control root with `Working branch: main` and is exempt from default-branch protection. `mstar dispatch validate` verifies the worktree path equals the control root, the working branch equals its checked-out branch, and probes **every declared target**: each must be Git-ignored and inside the control root — a repo whose `.gitignore` covers only `.mstar/plans/` passes for a target under `plans/`, while declaring a tracked target such as `.mstar/specs/…` is refused. Refusals are `dispatch.control-write.control-root-unresolved`, `dispatch.control-write.worktree-not-control`, `dispatch.control-write.branch-mismatch`, `dispatch.control-write.target-committable`, `dispatch.control-write.target-outside-control` and `dispatch.control-write.target-unverifiable`, each naming a recovery.
- **engine**: `parseAssignmentFields` parses `Worktree path` / `Write domain` / `Control write paths` through the same header grammar; `validateAssignmentFields` reports `assignment.field.write-domain-unknown`, `assignment.field.control-write-missing-worktree`, `assignment.field.control-write-missing-branch` and `assignment.field.control-write-paths-missing`; `dispatch.validate` skips `assertDefaultBranchProtected` for control-domain Assignments and checks control-root identity plus per-target ownership via `readMainWorktree` and `probePathOwnership`.
- **cli**: `mstar dispatch validate` accepts a control-domain Assignment on `main` and prints the new refusal codes with their recovery.
- Updated `mstar-branch-worktree` (control-domain write subsection), `mstar-dispatch-gates` (Assignment field list) and `mstar-roles/references/project-manager/dispatch-and-assignment.md` (template + field table).

- 新增可选 Assignment 字段 **`Write domain: control`**（取值 `control` | `work`；缺省 `work`）及其配套字段 **`Control write paths`**：列出该 Assignment 实际写入的过程目标（绝对路径，或相对 `Worktree path` 解析）。只写控制检出 gitignored 过程目标的 Assignment 可写 `Worktree path` = 控制根、`Working branch: main`，并豁免默认分支保护。`mstar dispatch validate` 核验 worktree 路径等于控制根、工作分支等于其当前检出分支，并**逐个探测声明的目标**：每个目标必须被 Git 忽略且位于控制根内——仓库只忽略 `.mstar/plans/` 时，声明 `plans/` 下的目标即通过；声明被跟踪的目标（如 `.mstar/specs/…`）会被拒。拒绝码为 `dispatch.control-write.control-root-unresolved`、`dispatch.control-write.worktree-not-control`、`dispatch.control-write.branch-mismatch`、`dispatch.control-write.target-committable`、`dispatch.control-write.target-outside-control` 与 `dispatch.control-write.target-unverifiable`，各带明确修复路径。
- **engine**：`parseAssignmentFields` 用同一 header 语法解析 `Worktree path` / `Write domain` / `Control write paths`；`validateAssignmentFields` 报 `assignment.field.write-domain-unknown`、`assignment.field.control-write-missing-worktree`、`assignment.field.control-write-missing-branch` 与 `assignment.field.control-write-paths-missing`；`dispatch.validate` 对控制域 Assignment 跳过 `assertDefaultBranchProtected`，并通过 `readMainWorktree` 与 `probePathOwnership` 核验控制根身份与逐目标归属。
- **cli**：`mstar dispatch validate` 接受 `main` 上的控制域 Assignment，并以拒绝码 + 修复路径报出新失败。
- 更新 `mstar-branch-worktree`（控制域写入小节）、`mstar-dispatch-gates`（Assignment 字段清单）与 `mstar-roles/references/project-manager/dispatch-and-assignment.md`（模板 + 字段表）。
