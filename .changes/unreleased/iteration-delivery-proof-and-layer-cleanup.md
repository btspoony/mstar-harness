category: Breaking
packages: root, engine, commands, dsh
---

- **An iteration's terminal close proves its delivery chain.** `verifyDeliveryEvidence` now dispatches by route: a development plan keeps its merge proof, a report-only plan keeps its registered completion policy, and an iteration proves that its `branch.integration` tip is an ancestor of the resolved `branch.target`, refusing with `PHASE6_DELIVERY_MERGE_UNPROVEN` otherwise. The proof reads the workflow's recorded integration checkout first and falls back to plan-row worktrees, so routine post-Done cleanup of the plan checkouts no longer refuses a close whose chain did land; the standalone plan route still reads only plan-row worktrees.
- **The phase gate returns two transitions.** `evaluatePhaseGate` no longer reports a PR stage after close: it returns `phase-2-execute` while a registered plan is not Done and `phase-3-close` once every plan is Done, with `ok` — not the transition name — as the readiness signal, so `phase-3-close` is writable exactly when the close is legitimate. The third, PR-stage member is removed from `PhaseTransition` and from dsh's `IterationGateView.transition`; every consumer switching on that value must read `ok` instead, and the retired name it carried now fails the drift guard in a code span as it does in prose.
- **Worktree cleanup knows layer refs and refuses an open PR base.** The engine-defined `iteration-stack/<workflow-id>/sNN` namespace attributes to its owning workflow, carries no `planId`, and evaluates merged evidence against `branch.target`; every other ref is still attributed only from recorded rows. While a layer ref is a cleanup candidate, one base-filtered `gh pr list --repo <origin owner/name> --base <layer-ref> --state open` probe runs per candidate, pinned to the repository `git remote get-url origin` resolves to, and a layer ref that is another open PR's base refuses with `cleanup.refuse.open-pr-base`; a probe that cannot run, parse, resolve or complete under its own cap fails closed on the same refusal, while a run with no layer-ref candidate spawns no probe.
- **Two recovery paths replace two impossible ones.** A genuinely unprovable iteration close is now recorded honestly with `mstar workflow lifecycle --status stopped --reason <why>` instead of being stranded behind a state it cannot reach, and the refusal text names it; a landed layer ref becomes cleanable evidence against `branch.target` instead of a foreign ref, with the open-PR-base refusal naming the one condition — the PR using that ref as base — that the operator must resolve before the ref is removed.

- **迭代终态关闭现证明其交付链。** `verifyDeliveryEvidence` 按路线分派：development plan 保留其合并证明、report-only plan 保留其已注册完成策略，迭代则证明 `branch.integration` 的 tip 是解析后 `branch.target` 的祖先，否则以 `PHASE6_DELIVERY_MERGE_UNPROVEN` 拒绝。该证明先读工作流记录的 integration checkout，再回落到 plan 行 worktree，因此交付确已落地的关闭不再被常规的 plan checkout 清理卡住；standalone plan 路线仍只读 plan 行 worktree。
- **phase gate 现只返回两个 transition。** `evaluatePhaseGate` 不再报告 close 之后的 PR 阶段：注册 plan 未全部 Done 时返回 `phase-2-execute`，全部 Done 后返回 `phase-3-close`，就绪信号是 `ok` 而非 transition 名，故 `phase-3-close` 恰在 close 合法时可写入。第三段（PR 阶段）成员已从 `PhaseTransition` 与 dsh 的 `IterationGateView.transition` 中移除；所有按该值分支的消费者须改读 `ok`，且该退役拼写现与散文一样在代码段中被 drift guard 拒绝。
- **worktree cleanup 认识 layer ref 并拒绝 open PR base。** 引擎定义的 `iteration-stack/<workflow-id>/sNN` 命名空间归属其 workflow、不带 `planId`，并以 `branch.target` 评估合并证据；其他 ref 仍只按记录行归属。当 layer ref 成为清理候选时，逐候选执行一次带 base 过滤的 `gh pr list --repo <origin owner/name> --base <layer-ref> --state open` 探测，仓库锚定为 `git remote get-url origin` 解析出的仓库；作为其他 open PR base 的 layer ref 以 `cleanup.refuse.open-pr-base` 拒绝；探测无法执行、解析、定位仓库或在自身上限内完成时同样 fail closed；无 layer-ref 候选时不发起任何探测。
- **两条恢复路径替代两条不可能的路径。** 确实无法证明的迭代关闭现以 `mstar workflow lifecycle --status stopped --reason <why>` 如实记录，而不再被困在其无法到达的状态之后，拒绝文案也点名该路径；已落地的 layer ref 成为可按 `branch.target` 清理的证据，而不再被视为外来 ref，`cleanup.refuse.open-pr-base` 则点明操作者必须先解决的唯一条件——以该 ref 为 base 的 PR。
