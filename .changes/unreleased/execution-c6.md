- New `packages/cli/src/execution-migrate.ts` registers the **EXECUTION operator family** of contract §3.2 under the existing `mstar store` group: `store execution preview | apply | activate | retire | abort | restore-preview | restore | export`. Every verb validates its own flags and forwards the operator's reviewed documents into the real engine operations — `previewExecutionMigration`, `collectExecutionCoverage`, `applyExecutionMigration`, `activateExecutionMigration`, `retireExecutionSources`, `abortExecutionMigration`, `previewExecutionRestore`, `restoreExecutionBackup` and `exportExecutionState` — with no placeholder handler, no fallback authority and no migration logic in the CLI.
- The mutating forms take the exact artifact of the boundary they cross and fail closed when one is missing (exit 2): `apply` needs the version-2 `--manifest`, its `--coverage` set, the recovery-point RECEIPT document from `mstar store backup --json` as `--backup` and the reviewed `--inventory` when the manifest records one; `activate` needs `--manifest`, `--coverage` (its digest is the approval) and the operator `--attestation`; `retire`/`abort` address the recorded manifest by identity and require `--inventory` / `--reason` respectively; `restore` requires the `--preview` document and the EXACT `--accept-loss-digest` (there is no default yes). A coverage set of another manifest, a coverage request without the inventory it needs and a relative path are all usage refusals decided before any IO.
- `preview` stays read-only discovery and, with `--inventory --coverage-out`, collects §4.2 coverage of the same frozen manifest; `restore-preview` is the read-only §8 loss inventory; `export` writes the canonical diagnostic view whose artifact carries session rows without identities (the dropped key names travel in `redactedKeys`) and which no writer accepts. Envelope on stdout with `--json` is `{ok:true,route:"execution",operation,data}` / `{ok:false,route:"execution",operation,code,message}`, with engine codes preserved verbatim (exit 0 ok, 1 refusal, 2 usage); the shared tail handler now also answers commander-level usage errors of this family with that same object.
- Route discipline: `store activate` remains the ISSUE/CATALOG barrier and is never aliased to execution activation — the execution barrier is `store execution activate`, and the family never calls the issue/catalog activation, `activateStore` or the retirement path of the issue/catalog migration. Current-epoch stopped-coordinator recovery stays the already-registered `mstar session recover` under an independently acquired caller identity; no verb here claims lease recovery, and a migrated held lease is represented at its own epoch rather than adopted.
- New regression `packages/cli/test/execution-migrate.test.ts` drives the real CLI entry over temporary populated workspaces: preview → coverage → apply → activate (with a real stop attestation naming every imported owner) → stopped-coordinator recovery under an independent identity → retire, with a stable replay per verb, a missing coverage/attestation/loss-confirmation refusal that writes no authority, the exact-loss restore gate, the redacted export, and the issue/catalog versus execution route distinction.

- 新增 `packages/cli/src/execution-migrate.ts`，在既有 `mstar store` 组下注册契约 §3.2 的**执行运维命令族**：`store execution preview | apply | activate | retire | abort | restore-preview | restore | export`。每个动词只校验自身旗标，并把操作者已审阅的文档转发进真实引擎函数——`previewExecutionMigration`、`collectExecutionCoverage`、`applyExecutionMigration`、`activateExecutionMigration`、`retireExecutionSources`、`abortExecutionMigration`、`previewExecutionRestore`、`restoreExecutionBackup`、`exportExecutionState`——无占位处理器、无备用授权、CLI 内不含迁移逻辑。
- 变更类动词都要求它所跨越边界的精确产物，缺失即 fail-closed（exit 2）：`apply` 需要 v2 `--manifest`、其 `--coverage`、来自 `mstar store backup --json` 的恢复点 **receipt 文档**（`--backup`），以及当 manifest 记录了显式范围时所需的 `--inventory`；`activate` 需要 `--manifest`、`--coverage`（其 digest 即批准）与操作者 `--attestation`；`retire`/`abort` 以身份寻址已记录的 manifest，并分别要求 `--inventory` / `--reason`；`restore` 需要 `--preview` 文档与**精确**的 `--accept-loss-digest`（不存在默认同意）。属于另一个 manifest 的 coverage 集合、缺少所需 inventory 的 coverage 请求以及相对路径，都是在任何 IO 之前决定的 usage 拒绝。
- `preview` 保持只读发现，并在 `--inventory --coverage-out` 下采集同一冻结 manifest 的 §4.2 coverage；`restore-preview` 是只读的 §8 损失清单；`export` 写出规范诊断视图——其产物只含无身份的 session 行（被丢弃的键名在 `redactedKeys` 中列出），且没有任何 writer 接受该产物。`--json` 的 stdout 信封为 `{ok:true,route:"execution",operation,data}` / `{ok:false,route:"execution",operation,code,message}`，引擎错误码原样保留（exit 0 成功、1 拒绝、2 usage）；共享尾处理器现在也用同一对象回应本族的 commander 级 usage 错误。
- 路由纪律：`store activate` 仍是 **issue/catalog** 屏障，绝不与执行激活混同——执行屏障是 `store execution activate`；本族从不调用 issue/catalog 激活、`activateStore` 或 issue/catalog 迁移的退休路径。当前 epoch 的停止协调者恢复仍是既有的 `mstar session recover`（独立获取的调用者身份）；本族任何动词都不声称租约恢复，迁移后的 held lease 按其自身 epoch 保留而不被接管。
- 新增回归 `packages/cli/test/execution-migrate.test.ts`：以真实 CLI 入口在临时填充式工作区上跑通 preview → coverage → apply → activate（真实停止断言书，命名每个被导入的 owner）→ 独立身份下的停止协调者恢复 → retire，每个动词重放稳定；缺 coverage/attestation/loss 确认均拒绝且不写入任何授权；restore 严格按精确损失摘要放行；export 已完成脱敏；并核对 issue/catalog 与执行路由的区分。
