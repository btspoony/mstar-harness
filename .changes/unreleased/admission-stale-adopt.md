- Made admission cost proportional to contention (**fixes #308, adoption half**): a `bind` on a prepared row **nobody else holds** (no `coordination.session` at all, or the binder's own claim binding — the D0 claim row — and no `coordination.handoff`) whose addressed Assignment bytes changed after `prepare` no longer hard-stops. The bind refreshes the row's pin to the bytes it actually bound and appends one `coordination.self_amendments` entry to the workflow snapshot — `{at, session_id, old_sha256, new_sha256, operation_id, prepared_by_matches?}` — in the same locked write, then continues as a normal bind. A row held or handed off by **another** session keeps the terminal `coordination.assignment-stale`, a missing Assignment is never adopted, and the decision rests on the row's unclaimed state alone: the file route's `--session-id` is caller-asserted, so no `prepared_by === caller` gate exists.
- Added the append-only `coordination.self_amendments` audit to the snapshot schema and its strict validator (exact keys, bare sha256 digests, boolean annotation) beside `identity_recoveries`; the record is provenance only — nothing in the engine reads it to decide anything and no gate may be derived from it. A workflow whose snapshot carries no `coordination` block (reachable now that the claim bootstrap needs no coordinator seat) refuses the amendment rather than refreshing a pin unrecorded. The coordinator is the post-hoc verifier: `skills/mstar-iteration/references/plan-scoped-pm.md` §2/§2.5/§6 document reading it (and the row's `prepared_by` / session binding) before `accept`.
- The audit survives the DB migration: `execution-migrate` projects `coordination.self_amendments` into the imported workflow header verbatim, exactly as it already carries `identity_recoveries`.

- 让准入成本与争用程度成正比（**修复 #308 的 adoption 一半**）：当 bind 面对一个 **非他人持有**（完全无 `coordination.session`，或该 session 就是 binder 自己的 claim 绑定——即 D0 claim 行；且无 `coordination.handoff`）且其 addressed Assignment 在 `prepare` 之后被改动的已 prepare 行时，不再硬停。该 bind 会在同一次加锁写入中把该行 pin 刷新为它实际绑定的字节，并向 workflow 快照追加一条 `coordination.self_amendments` 记录——`{at, session_id, old_sha256, new_sha256, operation_id, prepared_by_matches?}`——随后继续正常 bind。被**其他** session 持有或已 handoff 的行保持终态 `coordination.assignment-stale`，Assignment 不存在时绝不 adopt；判定不对调用方做认证：文件路线的 `--session-id` 由调用方自述，因此不存在 `prepared_by === caller` 门禁，他人的 session id 仍然只得到原有拒绝。
- 在快照 schema 中新增仅追加的 `coordination.self_amendments` 审计及其严格校验器（键集固定、裸 sha256、布尔注解），与 `identity_recoveries` 并列；该记录只是存证——引擎不读取它做任何决定，也不得由它派生门禁。若 workflow 快照没有 `coordination` 块（claim bootstrap 不需要 coordinator 席位，因此该状态可达），则不做无法留痕的刷新，而是以 `coordination.assignment-stale` 拒绝并提示先绑定该 workflow 的 coordinator 席位。coordinator 是事后验证者：`skills/mstar-iteration/references/plan-scoped-pm.md` §2/§2.5/§6 描述在 `accept` 之前读取它（以及该行的 `prepared_by` / session 绑定）。
- 该审计可跨 DB 迁移保留：`execution-migrate` 将 `coordination.self_amendments` 原样投影到导入的 workflow header，与既有的 `identity_recoveries` 处理一致。
